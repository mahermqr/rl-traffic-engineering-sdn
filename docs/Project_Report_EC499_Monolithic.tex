% Abstract
\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

Traditional Internet Protocol (IP) routing protocols, including Open Shortest Path First (OSPF, RFC 2328), Dijkstra's Shortest Path First (SPF), and Equal-Cost Multi-Path (ECMP), compute packet forwarding decisions based on static hop counts or fixed administrative link metrics. When dynamic traffic surges, asymmetric workload spikes, or high-bandwidth elephant flows materialize, these static protocols persistently steer traffic onto identical shortest paths. This behavior precipitates severe core switch bottlenecks, high queuing latency, catastrophic packet delay variation (jitter), and buffer overflow packet loss, while redundant lateral mesh links remain substantially underutilized.

This graduation project designs, implements, and rigorously evaluates an autonomous, production-grade \textbf{Deep Reinforcement Learning (DRL) Traffic Engineering Platform} built on the \textbf{Ryu OpenFlow 1.3 SDN Controller}, the \textbf{Mininet Network Emulator}, and the \textbf{PyTorch Deep Learning Framework}. The system implements a \textbf{Dueling Double Deep Q-Network (D3QN)} policy engine with \textbf{Prioritized Experience Replay (PER)} running over an $O(\log N)$ binary SumTree data structure. By continuously ingesting normalized 10-dimensional network state vectors (capturing real-time link loads, end-to-end queuing delays, RFC 3393 jitter variation, and buffer overflow risks), the D3QN agent dynamically steers incoming unicast flows across diversity-aware candidate paths synthesized via Yen's $K$-Shortest Paths and edge-disjoint routing algorithms.

The platform is evaluated in an automated head-to-head tournament against five established routing baselines---\textbf{OSPF (RFC 2328)}, \textbf{Dijkstra SPF}, \textbf{ECMP}, \textbf{Widest Shortest Path (WSP/CSPF)}, and \textbf{Greedy Least Loaded Routing (LLR)}---across five standard network topologies: Hierarchical Tree, Fat-Tree Clos ($k=4$), Abilene US Backbone, NSFNet Continental Mesh, and Spine-Leaf data center fabrics. Furthermore, zero-shot transferability is verified on dynamically generated arbitrary random graphs up to 35 nodes without neural retraining. Under dynamic flow accumulation, the D3QN agent achieves up to \textbf{$-64.4\%$} bottleneck link reduction on Fat-Tree Clos and \textbf{$-77.6\%$} on Spine-Leaf fabrics compared to Dijkstra SPF, decreases path latency from 34.71~ms down to \textbf{2.67~ms}, suppresses network jitter by over \textbf{$95\%$}, and eliminates buffer packet dropouts (\textbf{$< 0.015\%$ loss}), while sustaining neural inference throughput exceeding \textbf{$2,400\text{ to } 4,600\text{ decisions/second}$} on commodity CPU hardware. Finally, a critical theoretical analysis details the operational boundaries of the architecture, including candidate path synthesis overhead, WAN propagation delay trade-offs, and TCAM rule management.

\vspace{0.8cm}

\noindent\textbf{Keywords:} Software-Defined Networking (SDN), OpenFlow 1.3, Deep Reinforcement Learning (DRL), Dueling Double DQN, Prioritized Experience Replay, Traffic Engineering, Quality of Service (QoS), Network Telemetry.

The key pillars of the project are:

\begin{enumerate}[label=\textbf{\Roman*.}]
    \item \textbf{Decoupled Control and Machine Learning Pipeline}:
    By pairing the event-driven Ryu OpenFlow 1.3 controller with PyTorch in an asynchronous multi-threaded pipeline, the system completely isolates packet handling from gradient backpropagation. Production packet routing executes forward matrix inference in $<0.05\text{ ms}$, sustaining up to $4,625\text{ decisions/second}$ on commodity CPU hardware.
    
    \item \textbf{Topological Normalization and Zero-Shot Transferability}:
    Rather than encoding absolute switch or port numbers into the neural network, the state space is formulated as a 10-dimensional vector of normalized bottleneck loads, hop ratios, and propagation delays bounded strictly in $[0.0, 1.0]$. This mathematical abstraction decouples the policy from graph cardinality, enabling the pre-trained neural network to achieve immediate anti-congestion relief on unseen 15, 25, and 35-node random graphs without retraining.
    
    \item \textbf{Asymptotic Congestion Barrier Optimization}:
    To enforce proactive bottleneck avoidance, we derived a piecewise non-linear barrier penalty function ($\Phi_{\text{cong}}$). When link utilization exceeds 70\%, the penalty escalates asymptotically toward infinity as utilization approaches 100\%. This mathematical gradient dwarfs linear hop penalties, compelling the agent to detour flows onto lateral bypasses before physical switch queues can overflow.
    
    \item \textbf{Rigorous 5-Topology Tournament Validation}:
    Across 150-flow closed-loop dynamic traffic accumulation trials, D3QN outperformed OSPF (RFC 2328), Dijkstra SPF, ECMP, WSP, and LLR across all five evaluated topologies (Hierarchical Tree, Fat-Tree Clos, Abilene US Backbone, NSFNet Continental Mesh, and Spine-Leaf Fabric). Peak bottleneck utilization was slashed from $86.7\%$ down to $19.4\%$ on Spine-Leaf, end-to-end latency dropped by up to $92.3\%$, jitter was suppressed by over $85\%$--$95\%$, and packet loss was virtually eliminated ($0.010\%$).
    
    \item \textbf{Production Operations and Defense Readiness}:
    The software architecture includes an intelligent host-tracking ARP engine that eliminates switching loops without requiring Spanning Tree Protocol (STP), native OpenFlow Select Group WCMP flow splitting, sub-millisecond Fast Failover protection, an interactive HTML5 canvas telemetry dashboard, 26 passing automated unit tests, and an authoritative 25-question defense preparation guide.
\end{enumerate}

\chapter{Introduction}
\label{chap:intro}

\section{Evolution of Modern Network Infrastructures}
Communication networks have evolved from modest, host-centric, packet-switched topologies into the foundational backbone of contemporary global commerce, scientific computing, cloud infrastructure, and civil communication. Modern hyper-scale data centers, telecommunication service provider backbones, multi-tenant cloud fabrics, and content distribution networks (CDNs) routinely interconnect hundreds of thousands of bare-metal servers and millions of concurrent virtual machines (VMs) and containerized microservices. These infrastructures handle data transfers exceeding exabytes per month, supporting bandwidth-intensive and latency-hyper-sensitive applications such as real-time financial algorithmic trading, remote robotic tele-surgery, autonomous vehicular telemetry, ultra-high-definition interactive telepresence, distributed machine learning gradient synchronization, and exascale cloud storage replication.

As modern workloads have shifted toward distributed, microservice-oriented cloud applications, network traffic patterns have undergone a fundamental topological transformation. In legacy campus and enterprise networks, traffic predominantly followed a vertical ``North-South'' axis, flowing from external edge clients across perimeter firewalls and border gateways down to localized enterprise database servers. Conversely, within contemporary multi-tenant cloud data centers and distributed analytics clusters (e.g., Apache Spark, Kubernetes, Ceph, and distributed PyTorch/TensorFlow training fabrics), over $80\%$ of all aggregate network traffic travels horizontally along an ``East-West'' trajectory between adjacent server racks and internal compute nodes.

This immense surge in horizontal East-West communication is characterized by extreme burstiness, heavy-tailed flow-size distributions, and unpredictable spatial volatility. High-bandwidth, long-lived bulk data transfers---commonly referred to in networking literature as ``elephant flows'' (e.g., distributed dataset shards, VM live migrations, database backups)---coexist on shared switching infrastructure alongside millions of short-lived, latency-critical transactional RPCs, known as ``mice flows'' (e.g., web queries, DNS lookups, distributed lock coordination). When these heterogeneous traffic demands traverse static network topologies, managing link utilization, switch buffer occupancy, and packet queuing delay becomes a formidable engineering challenge.

\section{The Traffic Engineering Problem}
Traffic Engineering (TE) is the operational domain within computer network engineering concerned with optimizing the performance of operational networks. The core objective of TE is to dynamically guide, steer, and map network traffic flows across physical or virtual network topologies in a manner that maximizes aggregate network throughput, balances utilization across all available transmission links, avoids localized core bottlenecks, minimizes end-to-end packet transmission latency and packet delay variation (jitter), and eliminates buffer overflow packet loss.

Mathematically, global traffic engineering across a multigraph $G = (V, E)$ with $|V|$ switching nodes and $|E|$ directed transmission edges can be formalized as an instance of the classical Multi-Commodity Flow (MCF) problem. Let $\mathcal{K}$ denote the set of active traffic demands (commodities), where each commodity $k \in \mathcal{K}$ is defined by a source node $s_k \in V$, a destination node $t_k \in V$, and an instantaneous bandwidth demand $d_k > 0$. If $f_e^k$ represents the amount of commodity $k$ assigned to directed link $e \in E$, the optimal routing allocation seeks to optimize a multi-objective utility function:
\begin{equation}
    \min_{f} \quad \sum_{e \in E} \Phi_e\left( \frac{\sum_{k \in \mathcal{K}} f_e^k}{C_e} \right)
    \label{eq:te_general_objective}
\end{equation}
subject to flow conservation constraints at every node $v \in V$:
\begin{equation}
    \sum_{e \in \delta^+(v)} f_e^k - \sum_{e \in \delta^-(v)} f_e^k = \begin{cases}
        d_k & \text{if } v = s_k \\
        -d_k & \text{if } v = t_k \\
        0 & \text{otherwise}
    \end{cases} \quad \forall v \in V, \, \forall k \in \mathcal{K}
    \label{eq:flow_conservation_intro}
\end{equation}
and physical link bandwidth capacity constraints:
\begin{equation}
    \sum_{k \in \mathcal{K}} f_e^k \le C_e \quad \forall e \in E
    \label{eq:capacity_constraint_intro}
\end{equation}
where $\delta^+(v)$ and $\delta^-(v)$ represent the sets of edges leaving and entering node $v$, respectively, $C_e$ denotes the maximum physical line rate of link $e$, and $\Phi_e(\cdot)$ is an increasing, convex penalty function modeling link congestion and queuing delay.

While the basic continuous multi-commodity flow formulation with fractional flow splitting can be solved in polynomial time via interior-point linear programming methods, real-world packet-switched routing introduces unsplittable (integer) flow constraints to prevent TCP packet reordering, binary forwarding rules, and discrete switch buffer capacities. Under unsplittable flow requirements, the traffic engineering optimization problem becomes strictly $\mathcal{NP}$-hard. In a production network subject to continuous, sub-second traffic variations, computing global linear programming re-allocations in real time is computationally intractable. Consequently, production networks have historically relied on distributed, heuristic routing protocols.

\section{Pathological Failures of Traditional Distributed IP Routing}
Traditional distributed Internet Protocol (IP) networks rely on Interior Gateway Protocols (IGPs) such as Open Shortest Path First (OSPF, RFC 2328) and Intermediate System to Intermediate System (IS-IS) to determine forwarding paths. In these protocols, autonomous routers exchange Link-State Advertisements (LSAs) and execute Dijkstra's Shortest Path First (SPF) algorithm to construct local next-hop routing tables. Each physical link $e$ is assigned a static administrative weight $w_e \in \mathbb{Z}^+$, configured by network administrators inversely proportional to link capacity:
\begin{equation}
    w_e = \max\left(1, \, \text{round}\left(\frac{\text{Reference Bandwidth}}{C_e}\right)\right)
\end{equation}
Although distributed shortest-path routing is robust against single-point control plane failures, it exhibits fundamental structural pathologies that render it incapable of achieving adaptive traffic engineering:

\begin{enumerate}[label=\textbf{\arabic*.}]
    \item \textbf{Oblivious Metric Forwarding}: The administrative weights assigned to links are completely decoupled from real-time network dynamics, buffer occupancy, and instantaneous link utilization. An administrative cost of 1 on a 100~Mbps trunk line remains fixed at 1 whether the link carries 2~Mbps of traffic or is operating at 99.5\% saturation on the verge of catastrophic packet drop. All incoming flows continue to be funneled along the same static path until physical queue starvation or packet drop occurs.
    \item \textbf{Systemic Core Bottlenecks in Hierarchical Fabrics}: Modern enterprise campus, telecommunication, and data center topologies are structured hierarchically (e.g., 3-tier Tree, Multi-Stage Clos, Fat-Tree, and Spine-Leaf architectures). In these topologies, shortest-path algorithms calculate that all cross-domain or inter-pod communications must traverse the central aggregation and core switches. Under heavy load, this funneling effect concentrates traffic onto a tiny subset of central transit links, driving their utilization into saturation while abundant, redundant lateral bypass links, diagonal cross-connections, and alternative spines sit completely idle.
    \item \textbf{Destructive Hash Polarization in Equal-Cost Multi-Path (ECMP)}: To overcome the limitation of a single shortest path, modern switches deploy Equal-Cost Multi-Path (ECMP). When multiple paths of identical minimum metric exist between a source and destination, the switch hashes the packet's 5-tuple (Source IP, Destination IP, Protocol, Source Port, Destination Port) to assign the packet to one of the equal-cost egress ports:
    \begin{equation}
        h = \text{CRC32}(\text{5-Tuple}) \pmod{|\mathcal{P}_{\text{ECMP}}|}
    \end{equation}
    Despite its widespread deployment, ECMP suffers from severe operational flaws:
    \begin{itemize}
        \item \emph{Inability to Exploit Near-Equal Paths}: ECMP can only distribute traffic across paths that share the exact same administrative cost. If an alternative lateral path has a cost higher by even a single hop, ECMP completely ignores it, even if the primary shortest path is 100\% congested and the lateral path is 0\% loaded.
        \item \emph{Elephant Flow Collisions}: ECMP performs oblivious flow-level hashing without awareness of flow sizes or bitrates. When multiple high-bandwidth elephant flows hash to the same egress port (hash collision), the shared link buffer is rapidly exhausted, inducing severe head-of-line blocking and packet loss for all co-located latency-sensitive mice flows.
        \item \emph{Hash Polarization}: In multi-stage Clos architectures, identical hashing algorithms implemented across consecutive switch tiers often map the same subset of flows onto identical downstream paths, concentrating traffic onto a fraction of available fabric links.
    \end{itemize}
    \item \textbf{Instability and Oscillations in Dynamic Heuristics}: Recognizing the limitations of static routing, researchers proposed dynamic greedy heuristics, such as Widest Shortest Path (WSP) and Least Loaded Routing (LLR). However, in closed-loop systems with discrete telemetry polling intervals, greedy heuristics trigger devastating \textbf{herd behavior oscillations}. Because telemetry updates occur periodically (e.g., every 1 to 3 seconds), all flows arriving within an update window observe the exact same link as the ``least loaded.'' Consequently, all flows are routed onto that single link simultaneously, driving it into severe congestion before the next polling interval, causing the algorithm to violently shift all subsequent traffic to another link, resulting in perpetual instability and route flapping.
\end{enumerate}

\section{The Software-Defined Networking (SDN) Paradigm}
Software-Defined Networking (SDN) represents a revolutionary paradigm shift that breaks the ossified, vertically integrated architecture of traditional networking hardware. In traditional network appliances, the control plane (the algorithmic decision logic that determines where packets should flow) and the data forwarding plane (the hardware Application-Specific Integrated Circuits / ASICs that physically parse, match, and switch packet bits) are bundled tightly inside proprietary, vendor-locked chassis.

SDN resolves this architectural limitation by strictly decoupling the control plane from the underlying data plane:
\begin{itemize}
    \item \textbf{The Data Forwarding Plane}: Network switches (whether bare-metal hardware switches with Ternary Content-Addressable Memory / TCAM or virtual software switches like Open vSwitch / OVS) are stripped of complex distributed routing protocol daemons. Instead, switches act as fast, programmable packet-forwarding engines that match incoming packet headers against flow tables and execute programmed actions (e.g., output to port, push/pop VLAN/MPLS headers, drop, or encapsulate).
    \item \textbf{The Southbound Interface (OpenFlow 1.3)}: The OpenFlow protocol, standardized by the Open Networking Foundation (ONF), provides an open, vendor-agnostic programmatic communication protocol between the controller and the switches over a secure TCP/TLS control channel.
    \item \textbf{The Centralized Control Plane}: A logically centralized software entity---the SDN Controller (e.g., the Ryu SDN Framework)---maintains a continuous, global view of the entire network topology, host attachments, and link status. Through standard OpenFlow messages, the controller dynamically discovers topology links via the Link Layer Discovery Protocol (LLDP), polls fine-grained port and flow statistics, and proactively or reactively writes forwarding rules directly into switch flow tables.
\end{itemize}

Despite its transformative centralized visibility, a vanilla SDN controller does not inherently solve the traffic engineering problem: it merely provides the programmatic execution mechanism. The controller requires an intelligent, real-time algorithmic engine capable of ingesting raw telemetry data and computing optimal routing decisions dynamically.

\section{Deep Reinforcement Learning for Adaptive Traffic Engineering}
Designing an autonomous traffic engineering engine that operates in real time under bursty, non-stationary traffic demands requires moving beyond both static heuristics and computationally heavy linear programming solvers. Deep Reinforcement Learning (DRL) provides the ideal mathematical foundation for solving this closed-loop decision problem.

Reinforcement Learning (RL) formalizes autonomous decision-making as a Markov Decision Process (MDP). An autonomous agent interacts continuously with an environment through discrete time steps: the agent observes the current network state $s_t \in \mathcal{S}$, selects an action $a_t \in \mathcal{A}$ according to its internal policy $\pi(a_t|s_t)$, and transitions into a new state $s_{t+1}$ while receiving a scalar reward signal $r_t = \mathcal{R}(s_t, a_t)$. The objective of the RL agent is to learn an optimal policy $\pi^*$ that maximizes the expected cumulative discounted future reward over time:
\begin{equation}
    R_t = \sum_{k=0}^{\infty} \gamma^k r_{t+k}
\end{equation}
where $\gamma \in [0, 1)$ represents the temporal discount factor.

In recent years, the combination of reinforcement learning with deep neural networks (Deep Q-Networks / DQN) has achieved superhuman breakthroughs in complex control domains. However, directly applying standard DQN algorithms to computer network traffic engineering presents unique, domain-specific theoretical and practical challenges:
\begin{itemize}
    \item \textbf{Topological Generalizability}: Standard neural networks take fixed-size input vectors. If an RL agent is formulated to map raw link numbers or node IDs directly, the neural network becomes tied to a specific switch and link count, rendering the model useless if a single link fails or if the policy is transferred to a different network topology.
    \item \textbf{Action Space Scalability and Loop Freedom}: If the agent outputs unconstrained next-hop forwarding ports at each individual switch, the action space expands exponentially with network diameter, creating a high probability of transient forwarding loops, packet bouncing, and network black holes during exploration.
    \item \textbf{Multi-Objective Metric Trade-offs}: A realistic traffic engineering agent must balance multiple conflicting performance metrics simultaneously: maximizing throughput, avoiding bottleneck links, bounding propagation latency, suppressing jitter variation, minimizing packet dropouts, and preventing excessive hop detours.
    \item \textbf{Non-Stationary Experience Distribution}: Traffic microbursts and severe core jamming events are rare compared to steady-state background traffic. Under uniform experience replay sampling, the agent rarely samples critical congestion events, leading to catastrophic underfitting on emergency anti-congestion policies.
\end{itemize}

This graduation project directly resolves each of these fundamental challenges through a meticulously engineered, mathematically grounded Deep Reinforcement Learning Traffic Engineering platform.

\section{Graph Theory and Network Representation}
The physical and logical structure of a communication network is mathematically formalized as a directed multigraph $G = (V, E)$, where:
\begin{itemize}
    \item $V = \{v_1, v_2, \dots, v_{|V|}\}$ represents the finite set of switching elements (OpenFlow switches, routers, or packet forwarders).
    \item $E = \{e_1, e_2, \dots, e_{|E|}\} \subseteq V \times V$ represents the set of directed communication links interconnecting the switching nodes. A directed edge from switch $u$ to switch $v$ is denoted by $e = (u, v)$.
\end{itemize}

Each directed link $e = (u, v) \in E$ is characterized by a static and dynamic attribute tuple:
\begin{equation}
    e \sim \langle C(e), \, d_{\text{prop}}(e), \, \text{Loss}_{\text{base}}(e), \, u(e, t), \, q(e, t) \rangle
\end{equation}
where:
\begin{itemize}
    \item $C(e) \in \mathbb{R}^+$ denotes the maximum transmission bandwidth capacity of the link in Megabits per second (Mbps) or Gigabits per second (Gbps).
    \item $d_{\text{prop}}(e) \in \mathbb{R}^+$ denotes the physical propagation delay of the transmission medium, determined by the physical length $L_e$ of the fiber or copper link and the propagation speed of light in the medium $v_{\text{med}} \approx 2 \times 10^8\text{ m/s}$:
    \begin{equation}
        d_{\text{prop}}(e) = \frac{L_e}{v_{\text{med}}}
    \end{equation}
    \item $\text{Loss}_{\text{base}}(e) \ge 0$ represents the baseline bit-error-rate (BER) drop probability in the absence of buffer congestion.
    \item $u(e, t) \in [0.0, 1.0]$ represents the time-varying link utilization ratio at time $t$, defined as the ratio of instantaneous transmitted throughput to line capacity:
    \begin{equation}
        u(e, t) = \min\left(1.0, \, \frac{\text{Throughput}(e, t)}{C(e)}\right)
    \end{equation}
    \item $q(e, t) \in [0, K_e]$ represents the instantaneous queue buffer occupancy in packets or bytes, bounded by the physical output port buffer capacity $K_e$.
\end{itemize}

A path $\mathcal{P}_{s, t}$ from source node $s \in V$ to destination node $t \in V$ is defined as an alternating sequence of vertices and directed edges:
\begin{equation}
    \mathcal{P}_{s, t} = (v_0, e_1, v_1, e_2, v_2, \dots, e_m, v_m)
\end{equation}
such that $v_0 = s$, $v_m = t$, and $e_i = (v_{i-1}, v_i) \in E$ for all $i \in \{1, \dots, m\}$. The path is termed \emph{simple} (or loop-free) if all constituent vertices are distinct ($v_i \ne v_j$ for all $i \ne j$).

\section{Traditional IP Routing Protocols \& Algorithmic Mechanics}

\subsection{Dijkstra's Shortest Path First (SPF) Algorithm}
Dijkstra's Shortest Path First algorithm \cite{dijkstra1959note} represents the cornerstone of modern network graph computation. Given a directed graph $G = (V, E)$ with non-negative edge weight function $w: E \to \mathbb{R}^+$, Dijkstra's algorithm computes the shortest paths from a single source vertex $s \in V$ to all other vertices $v \in V \setminus \{s\}$.

\subsubsection{Algorithmic Formulation and Invariants}
The algorithm maintains two sets of vertices:
\begin{enumerate}
    \item $S$: The set of vertices whose final shortest-path distances from source $s$ have been definitively determined.
    \item $Q = V \setminus S$: A priority queue storing vertices whose shortest-path distances are currently tentative.
\end{enumerate}

Each vertex $v \in V$ maintains two state variables:
\begin{itemize}
    \item $d[v]$: The tentative upper bound on the distance from $s$ to $v$.
    \item $\pi[v]$: The predecessor node of $v$ along the current shortest path from $s$.
\end{itemize}

The execution proceeds through initialization and iterative edge relaxation, as formalized in Algorithm~\ref{alg:dijkstra_spf}.

\begin{algorithm}[htbp]
\caption{Dijkstra's Shortest Path First (SPF) Algorithm}
\label{alg:dijkstra_spf}
\begin{algorithmic}[1]
\REQUIRE Directed graph $G = (V, E)$, non-negative weight function $w: E \to \mathbb{R}^+$, source vertex $s \in V$
\ENSURE Distance array $d[v]$ and predecessor array $\pi[v]$ for all $v \in V$
\STATE \textbf{Initialize Single Source:}
\FORALL{$v \in V$}
    \STATE $d[v] \gets \infty$
    \STATE $\pi[v] \gets \text{NIL}$
\ENDFOR
\STATE $d[s] \gets 0$
\STATE $S \gets \emptyset$
\STATE Insert all vertices $v \in V$ into priority queue $Q$ keyed by $d[v]$
\WHILE{$Q \ne \emptyset$}
    \STATE $u \gets \text{EXTRACT-MIN}(Q)$
    \STATE $S \gets S \cup \{u\}$
    \FORALL{outgoing neighbor $v$ such that $(u, v) \in E$}
        \IF{$d[v] > d[u] + w(u, v)$}
            \STATE \COMMENT{Edge Relaxation Step}
            \STATE $d[v] \gets d[u] + w(u, v)$
            \STATE $\pi[v] \gets u$
            \STATE $\text{DECREASE-KEY}(Q, v, d[v])$
        \ENDIF
    \ENDFOR
\ENDWHILE
\RETURN $d, \pi$
\end{algorithmic}
\end{algorithm}

\subsubsection{Proof of Correctness}
The correctness of Dijkstra's algorithm rests on the \emph{greedy choice property} and the \emph{optimal substructure property} of shortest paths. We state and prove the primary invariant:

\begin{theorem}[Correctness of Dijkstra SPF]
For each vertex $u$ added to set $S$, $d[u] = \delta(s, u)$, where $\delta(s, u)$ denotes the true length of the shortest path from $s$ to $u$.
\end{theorem}

\begin{proof}
We prove this by mathematical induction on the size of set $S$.
\textbf{Base Case}: When $|S| = 1$, $S = \{s\}$. Since $w(e) \ge 0$ for all $e \in E$, no path from $s$ to $s$ containing one or more edges can have a total weight strictly less than $0$. Thus, $d[s] = 0 = \delta(s, s)$, establishing the base case.

\textbf{Inductive Step}: Assume the invariant holds for $|S| = k$. Let $u$ be the next vertex extracted from $Q$ and added to $S$, meaning $d[u] \le d[z]$ for all $z \in Q$. Suppose, for the sake of contradiction, that $d[u] > \delta(s, u)$. This implies that there exists an alternative, undiscovered path $\mathcal{P}$ from $s$ to $u$ whose total weight is strictly less than $d[u]$.

Because path $\mathcal{P}$ originates at $s \in S$ and terminates at $u \in Q$, there must exist an edge $(x, y)$ along $\mathcal{P}$ such that $x \in S$ and $y \in Q$. The subpath from $s$ to $y$ has weight:
\begin{equation}
    \delta(s, y) \le \text{weight}(\mathcal{P}) < d[u]
\end{equation}
Because $x \in S$, by the inductive hypothesis, $d[x] = \delta(s, x)$. When $x$ was added to $S$, the edge $(x, y)$ was relaxed, ensuring:
\begin{equation}
    d[y] \le d[x] + w(x, y) = \delta(s, x) + w(x, y) = \delta(s, y)
\end{equation}
Combining these inequalities yields:
\begin{equation}
    d[y] \le \delta(s, y) < d[u]
\end{equation}
Since both $y \in Q$ and $u \in Q$, the algorithm would have selected $y$ instead of $u$ in the $\text{EXTRACT-MIN}$ operation. This contradiction disproves our assumption, establishing that $d[u] = \delta(s, u)$ for all $u \in S$.
\end{proof}

\subsubsection{Computational Time Complexity Analysis}
The asymptotic time complexity of Dijkstra's algorithm depends critically on the underlying data structure utilized for priority queue $Q$:
\begin{itemize}
    \item \textbf{Unsorted Array}: $\text{EXTRACT-MIN}$ takes $O(|V|)$ time, while $\text{DECREASE-KEY}$ takes $O(1)$. Total execution time is $O(|V|^2 + |E|)$.
    \item \textbf{Binary Min-Heap}: Building the heap takes $O(|V|)$, $|V|$ $\text{EXTRACT-MIN}$ operations require $O(|V| \log |V|)$, and $|E|$ $\text{DECREASE-KEY}$ operations require $O(|E| \log |V|)$. Total time is:
    \begin{equation}
        T_{\text{binary}}(|V|, |E|) = O((|V| + |E|) \log |V|)
    \end{equation}
    \item \textbf{Fibonacci Heap}: $\text{EXTRACT-MIN}$ runs in $O(\log |V|)$ amortized time, while $\text{DECREASE-KEY}$ runs in $O(1)$ amortized time, yielding an optimal bound of:
    \begin{equation}
        T_{\text{fibonacci}}(|V|, |E|) = O(|E| + |V| \log |V|)
    \end{equation}
\end{itemize}

\subsection{Open Shortest Path First (OSPF, RFC 2328)}
Open Shortest Path First Version 2 (OSPFv2), standardized in IETF RFC 2328 \cite{moy1998ospf}, is the premier link-state Interior Gateway Protocol deployed in enterprise backbones. OSPF routers discover neighboring routers via the Hello protocol, form adjacencies, and exchange Link-State Advertisements (LSAs) through reliable flooding. Every router within an OSPF area constructs an identical Link-State Database (LSDB) representing graph $G = (V, E)$, over which it executes Dijkstra's SPF algorithm.

\subsubsection{OSPF Administrative Metric Formulation}
OSPF computes path costs as the sum of link interface costs. By RFC recommendation, an interface cost is an integer inversely proportional to configured line bandwidth:
\begin{equation}
    \text{Cost}(e) = \max\left(1, \, \text{round}\left( \frac{\text{Reference Bandwidth}}{C(e)} \right)\right)
    \label{eq:ospf_cost_formula}
\end{equation}
The historical default reference bandwidth is $100\text{ Mbps}$ ($10^8\text{ bps}$). Consequently, Table~\ref{tab:ospf_costs} details the default administrative costs assigned across standard link media.

\subsubsection{The Administrative Blindness Pathology}
Equation~\ref{eq:ospf_cost_formula} exposes the fatal flaw of OSPF: link costs are completely static. In high-speed data centers, Gigabit, 10GE, and 100GE links all collapse to a cost of 1. Crucially, as real-time traffic surges on an active link from $10\%$ to $99.9\%$ load, OSPF continues to broadcast a cost of 1. All network switches compute identical shortest paths, steering millions of additional packets directly into a saturated link, precipitating massive queue spikes and packet drops.

\subsection{Equal-Cost Multi-Path (ECMP)}
To mitigate single-path bottlenecking, modern routers implement Equal-Cost Multi-Path (ECMP). When Dijkstra's algorithm identifies $M$ distinct paths $\mathcal{P}_1, \dots, \mathcal{P}_M$ between source $s$ and destination $t$ that possess the exact same minimum cost $\text{Cost}(\mathcal{P}_i) = \min_j \text{Cost}(\mathcal{P}_j)$, the router distributes flows across all $M$ egress ports.

\subsubsection{Flow Hashing Mechanics}
To prevent packet reordering within a single TCP connection (which triggers spurious duplicate ACKs and throttles TCP sender congestion windows), ECMP hashes the packet's invariant 5-tuple:
\begin{equation}
    \text{Egress Port Index} = \text{Hash}(\text{IP}_{\text{src}}, \, \text{IP}_{\text{dst}}, \, \text{Proto}, \, \text{Port}_{\text{src}}, \, \text{Port}_{\text{dst}}) \pmod M
\end{equation}
where the hash is typically evaluated via CRC32 or Pearson's hash.

\subsubsection{Limitations of ECMP in Modern Fabrics}
Despite providing linear throughput scaling on perfectly symmetric topologies under uniform, small-flow workloads, ECMP exhibits severe vulnerabilities:
\begin{enumerate}
    \item \textbf{Asymmetric Cost Blindness}: ECMP cannot exploit near-equal-cost paths. In a topology where the primary shortest path has 2 hops and an alternative path has 3 hops, ECMP assigns $100\%$ of traffic to the 2-hop path, leaving the 3-hop path completely idle, even if the 2-hop path is experiencing $95\%$ packet loss.
    \item \textbf{Elephant Flow Collisions}: High-bandwidth elephant flows constitute less than $10\%$ of all flow counts but account for more than $80\%$ of total byte volume. When two or more elephant flows hash to the same egress port index, the port's output queue buffer is overwhelmed, creating severe congestion while parallel equal-cost paths remain severely underutilized.
\end{enumerate}

\subsection{Dynamic Routing Heuristics and the Herd Behavior Phenomenon}
To address static oblivious forwarding, dynamic heuristics were introduced:
\begin{itemize}
    \item \textbf{Widest Shortest Path (WSP / CSPF)}: Selects among candidate shortest paths the one that maximizes residual bottleneck bandwidth:
    \begin{equation}
        \mathcal{P}_{\text{WSP}} = \arg\max_{\mathcal{P} \in \mathcal{P}_{\text{min\_hops}}} \min_{e \in \mathcal{P}} \left( C(e) - \text{Throughput}(e, t) \right)
    \end{equation}
    \item \textbf{Least Loaded Routing (LLR)}: Greedily selects the path that minimizes a weighted linear combination of maximum link utilization and average path utilization:
    \begin{equation}
        \mathcal{P}_{\text{LLR}} = \arg\min_{\mathcal{P} \in \mathcal{P}_{\text{cand}}} \left( 0.65 \cdot \max_{e \in \mathcal{P}} u(e, t) + 0.35 \cdot \frac{1}{|\mathcal{P}|}\sum_{e \in \mathcal{P}} u(e, t) \right)
    \end{equation}
\end{itemize}

\subsubsection{Mathematical Formalization of Herd Behavior}
While intuitive, greedy heuristics suffer from systemic instability in discrete telemetry environments. Let $\Delta t_{\text{poll}}$ denote the discrete controller statistics polling interval (e.g., $\Delta t_{\text{poll}} = 3.0\text{ seconds}$). Suppose at time $t_0$, the controller measures link utilizations across two parallel candidate links $e_1$ and $e_2$:
\begin{equation}
    u(e_1, t_0) = 0.55, \quad u(e_2, t_0) = 0.20
\end{equation}
During the subsequent polling window $[t_0, t_0 + \Delta t_{\text{poll}}]$, suppose $N$ new high-bandwidth flows arrive with aggregate demand $D_{\text{agg}} = \sum_{i=1}^N d_i = 0.60 \cdot C$.

Because the controller's telemetry state remains static throughout the window $[t_0, t_0 + \Delta t_{\text{poll}}]$, every single one of the $N$ arriving flows independently evaluates link $e_2$ as the ``least loaded'' link:
\begin{equation}
    \mathcal{P}_{\text{LLR}}(i) = e_2 \quad \forall i \in \{1, \dots, N\}
\end{equation}
Consequently, link $e_2$ is immediately flooded with all incoming flows, driving its real-time utilization to:
\begin{equation}
    u(e_2, t_0 + \Delta t_{\text{poll}}) = 0.20 + 0.60 = 0.80
\end{equation}
At time $t_0 + \Delta t_{\text{poll}}$, the next polling cycle reports $u(e_1) = 0.55$ and $u(e_2) = 0.80$. Now, link $e_1$ is perceived as the ``least loaded.'' All subsequent flows arriving in the next window are routed exclusively to $e_1$, reversing the congestion and driving $e_1$ into saturation.

This perpetual oscillation between candidate links is termed the \textbf{Herd Behavior Phenomenon}. It degrades network performance by causing severe packet jitter, TCP ACK compression, and persistent buffer overshoots. Resolving herd behavior requires an intelligent agent that models expected downstream dynamics and distributes traffic probabilistically based on long-term value estimation.

\subsection{OpenFlow 1.3 Pipeline and Primitives}
OpenFlow 1.3 \cite{onf2012openflow} establishes the operational standard for SDN communication:

\subsubsection{Flow Table Structure and Flow Entries}
An OpenFlow 1.3 switch contains multiple flow tables numbered $0$ to $254$. Packet processing starts at Flow Table 0. Each flow entry contains:
\begin{itemize}
    \item \textbf{Match Fields}: Ingress switch port, Ethernet source/destination MAC addresses, EtherType, VLAN ID, IPv4 source/destination addresses, IP protocol (TCP/UDP/ICMP), and Layer 4 source/destination transport ports.
    \item \textbf{Priority}: An integer value ($0$ to $65535$). If multiple flow entries match a packet, the switch strictly executes the entry with the highest numerical priority.
    \item \textbf{Counters}: Total packets and bytes matched by this specific flow rule.
    \item \textbf{Instructions}: Directives modifying packet processing, such as \texttt{APPLY\_ACTIONS}, \texttt{WRITE\_ACTIONS}, \texttt{GOTO\_TABLE}, or \texttt{WRITE\_METADATA}.
    \item \textbf{Timeouts}:
    \begin{itemize}
        \item \texttt{idle\_timeout}: The flow entry is automatically purged by switch hardware if no packet matches the entry for this number of seconds.
        \item \texttt{hard\_timeout}: The flow entry is unconditionally purged after this number of seconds, regardless of traffic volume.
    \end{itemize}
\end{itemize}

\subsubsection{The Table-Miss Pipeline}
To handle previously unseen traffic, the controller installs a default \textbf{Table-Miss Flow Entry} at Priority 0 with a completely wildcarded match field (\texttt{parser.OFPMatch()}). When an incoming packet matches no higher-priority flow rule, the switch executes the table-miss instruction, encapsulating the packet header and buffering the payload, and sending an asynchronous \texttt{OFPPacketIn} event message to the controller.

\subsubsection{Group Tables}
OpenFlow 1.3 introduced Group Tables to enable advanced multi-path and resilient forwarding beyond simple port output:
\begin{itemize}
    \item \textbf{All Groups (\texttt{OFPGT\_ALL})}: Duplicates the packet to every action bucket in the group, used for broadcast and multicast emulation.
    \item \textbf{Select Groups (\texttt{OFPGT\_SELECT})}: Evaluates a switch-internal selection algorithm (e.g., 5-tuple hash) to execute a single bucket out of multiple candidate action buckets. Each bucket carries an explicit \texttt{weight}, enabling \textbf{Weighted Cost Multi-Path (WCMP)} flow splitting proportional to available path capacity.
    \item \textbf{Fast Failover Groups (\texttt{OFPGT\_FF})}: Evaluates the live hardware operational state of a specified \texttt{watch\_port}. If physical carrier signal is lost on the primary port, switch hardware immediately switches traffic to the alternate backup bucket within sub-milliseconds, bypassing controller communication.
\end{itemize}

\subsection{The Ryu SDN Controller Framework}
The Ryu SDN framework \cite{ryucontroller} is an open-source, component-based software-defined networking operating system implemented in Python. Ryu employs an asynchronous, event-driven concurrency model powered by Eventlet greenlets:
\begin{itemize}
    \item \textbf{Green Threads}: Lightweight user-space coroutines managed cooperatively by Eventlet's Hub reactor. Greenlets yield execution during blocking I/O, allowing a single CPU core to handle thousands of concurrent switch connections and telemetry polling cycles without POSIX thread synchronization overhead.
    \item \textbf{Event Dispatcher}: Decouples OpenFlow message decoders from application logic. When an OpenFlow message arrives over the TCP socket, Ryu parses the raw binary frame, instantiates an OpenFlow event object (e.g., \texttt{EventOFPPacketIn}), and dispatches it to registered event handlers using Python decorators (e.g., \texttt{@set\_ev\_cls(ofp\_event.EventOFPPacketIn, MAIN\_DISPATCHER)}).
\end{itemize}

\section{Deep Reinforcement Learning Theory}

\subsection{Markov Decision Processes (MDP)}
Reinforcement Learning models sequential decision-making under uncertainty as a discrete-time Markov Decision Process. An MDP is defined formally by the 5-tuple:
\begin{equation}
    \mathcal{M} = \langle \mathcal{S}, \, \mathcal{A}, \, \mathcal{P}, \, \mathcal{R}, \, \gamma \rangle
\end{equation}
where:
\begin{itemize}
    \item $\mathcal{S}$ is the set of all valid environmental states (the state space).
    \item $\mathcal{A}$ is the set of all available agent actions (the action space).
    \item $\mathcal{P}: \mathcal{S} \times \mathcal{A} \times \mathcal{S} \to [0, 1]$ is the state transition probability distribution, satisfying the Markov property:
    \begin{equation}
        \mathbb{P}(s_{t+1} = s' \mid s_t, a_t, s_{t-1}, a_{t-1}, \dots, s_0, a_0) = \mathbb{P}(s_{t+1} = s' \mid s_t, a_t)
    \end{equation}
    \item $\mathcal{R}: \mathcal{S} \times \mathcal{A} \to \mathbb{R}$ is the scalar reward function, returning reward $r_t = \mathcal{R}(s_t, a_t)$ upon executing action $a_t$ in state $s_t$.
    \item $\gamma \in [0, 1)$ is the temporal discount factor, balancing immediate vs. future rewards.
\end{itemize}

\subsection{Bellman Optimality and Q-Learning}
The value of taking action $a$ in state $s$ under policy $\pi(a|s)$ is defined by the action-value function $Q^\pi(s, a)$:
\begin{equation}
    Q^\pi(s, a) = \mathbb{E}_\pi \left[ \sum_{k=0}^\infty \gamma^k r_{t+k} \;\middle|\; s_t = s, a_t = a \right]
\end{equation}
The optimal policy $\pi^*$ maximizes the expected return:
\begin{equation}
    Q^*(s, a) = \max_\pi Q^\pi(s, a) \quad \forall s \in \mathcal{S}, \, \forall a \in \mathcal{A}
\end{equation}
The optimal action-value function satisfies the fundamental \textbf{Bellman Optimality Equation}:
\begin{equation}
    Q^*(s, a) = \mathcal{R}(s, a) + \gamma \sum_{s' \in \mathcal{S}} \mathcal{P}(s' \mid s, a) \max_{a' \in \mathcal{A}} Q^*(s', a')
    \label{eq:bellman_optimality}
\end{equation}
In model-free tabular Q-learning \cite{sutton2018reinforcement}, transitions $(s_t, a_t, r_t, s_{t+1})$ update tabular estimates iteratively via temporal difference (TD) learning:
\begin{equation}
    Q(s_t, a_t) \gets Q(s_t, a_t) + \alpha \Big( r_t + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t) \Big)
\end{equation}
where $\alpha \in (0, 1]$ is the learning rate.

\subsection{Deep Q-Networks (DQN)}
When state space $\mathcal{S}$ is continuous and high-dimensional, tabular representation becomes intractable. Mnih et al. \cite{mnih2015human} introduced Deep Q-Networks (DQN), approximating $Q^*(s, a) \approx Q(s, a; \theta)$ using a deep neural network parameterized by weights $\theta$. The network parameters are optimized by minimizing the mean squared Bellman error:
\begin{equation}
    \mathcal{L}(\theta) = \mathbb{E}_{(s, a, r, s') \sim \mathcal{D}} \left[ \left( r + \gamma \max_{a'} Q(s', a'; \theta^-) - Q(s, a; \theta) \right)^2 \right]
\end{equation}
where:
\begin{itemize}
    \item $\mathcal{D}$ represents an experience replay buffer storing observed transition tuples $e_t = (s_t, a_t, r_t, s_{t+1})$.
    \item $\theta^-$ represents the parameters of a separate \emph{target network}, periodically synchronized with the online network to prevent divergence and feedback loops.
\end{itemize}

\subsection{Double Deep Q-Networks (DDQN)}
Standard DQN suffers from systematic overestimation of Q-values due to the presence of the maximization operator $\max_{a'} Q(s', a'; \theta^-)$ in the target value:
\begin{equation}
    \mathbb{E}\left[ \max_{a'} Q(s', a') \right] \ge \max_{a'} \mathbb{E}\left[ Q(s', a') \right]
\end{equation}
In noisy network environments where link utilizations fluctuate, this maximization operator frequently overestimates suboptimal paths that randomly experienced low instantaneous delay.

Van Hasselt et al. \cite{vanhasselt2016deep} resolved this bias with Double DQN (DDQN). DDQN completely decouples action selection from action evaluation: the online network ($\theta$) selects the greedy action, while the target network ($\theta^-$) evaluates the Q-value of that selected action:
\begin{equation}
    Y_t^{\text{DoubleQ}} = r_t + \gamma \, Q\left(s_{t+1}, \, \arg\max_{a'} Q(s_{t+1}, a'; \theta_t); \, \theta_t^-\right)
    \label{eq:double_dqn_target}
\end{equation}
This mathematical decoupling provably eliminates overestimation bias, ensuring stable, monotonic value convergence.

\subsection{Dueling Q-Network Architecture}
In network routing, evaluating the intrinsic quality of a network state $V(s)$ is often critical regardless of which specific candidate path is chosen. For instance, if all paths leading to a destination are severely congested, the value of the state itself is universally poor.

Wang et al. \cite{wang2016dueling} introduced the Dueling architecture. The neural network splits after intermediate feature representations into two decoupled dense streams:
\begin{enumerate}
    \item A scalar \textbf{State-Value Stream} $V(s; \theta, \beta) \in \mathbb{R}^1$, evaluating the baseline quality of state $s$.
    \item An \textbf{Advantage Stream} $A(s, a; \theta, \alpha) \in \mathbb{R}^{|\mathcal{A}|}$, evaluating the relative benefit of taking candidate action $a \in \mathcal{A}$ compared to all other candidate actions.
\end{enumerate}

To ensure mathematical identifiability (so that $V(s)$ and $A(s, a)$ are uniquely recoverable from $Q(s, a)$), the mean advantage is subtracted from each action advantage:
\begin{equation}
    Q(s, a; \theta, \alpha, \beta) = V(s; \theta, \beta) + \left( A(s, a; \theta, \alpha) - \frac{1}{|\mathcal{A}|} \sum_{a' \in \mathcal{A}} A(s, a'; \theta, \alpha) \right)
    \label{eq:dueling_identifiability}
\end{equation}
Subtracting the mean ensures that $\sum_a (Q(s, a) - V(s)) = 0$, guaranteeing that the state value $V(s)$ accurately tracks the average return of the state while advantages $A(s, a)$ represent zero-centered relative deviations.

\subsection{Prioritized Experience Replay (PER)}
In uniform experience replay, all transitions in memory buffer $\mathcal{D}$ are sampled with equal probability $1/N$. In computer networks, critical congestion events, queue buffer overflows, and link failures occur infrequently. Under uniform sampling, the neural network spends most of its gradient updates re-learning trivial, uncongested steady-state conditions, failing to learn emergency anti-congestion policies.

Schaul et al. \cite{schaul2016prioritized} formulated Prioritized Experience Replay (PER). Each transition $i = (s_i, a_i, r_i, s_{i+1})$ is assigned a priority $p_i$ proportional to the magnitude of its absolute Temporal Difference (TD) error:
\begin{equation}
    p_i = |\delta_i| + \epsilon_{\text{per}}
    \label{eq:per_priority}
\end{equation}
where $\delta_i = Q(s_i, a_i; \theta) - Y_i^{\text{DoubleQ}}$ and $\epsilon_{\text{per}} = 10^{-5}$ is a small positive constant preventing zero probability transitions. The probability of sampling transition $i$ is defined by:
\begin{equation}
    P(i) = \frac{p_i^\alpha}{\sum_{k=1}^N p_k^\alpha}
    \label{eq:per_sampling_prob}
\end{equation}
where $\alpha \in [0, 1]$ controls prioritization strength ($\alpha = 0$ corresponds to uniform sampling; $\alpha = 1$ corresponds to fully greedy prioritization).

\subsubsection{Importance Sampling Weight Correction}
Non-uniform sampling alters the underlying state visitation frequency, introducing bias into stochastic gradient descent. To correct for this estimation bias, PER rescales gradient updates using Importance Sampling (IS) weights:
\begin{equation}
    w_i = \left( \frac{1}{N} \cdot \frac{1}{P(i)} \right)^\beta \Big/ \max_{j} w_j
    \label{eq:per_is_weights}
\end{equation}
where $\beta \in [0, 1]$ controls the degree of correction. To compensate for increasing gradient stability, $\beta$ is annealed linearly from $\beta_0 = 0.4$ up to $1.0$ at the conclusion of training. The weighted loss function minimized by the optimizer is:
\begin{equation}
    \mathcal{L}_{\text{PER}}(\theta) = \frac{1}{B} \sum_{i=1}^B w_i \cdot \mathcal{L}_{\text{Huber}}(\delta_i)
\end{equation}

\section{Network Topology and Multigraph Mathematical Formalism}
We model a software-defined communication network as a directed multigraph $G = (V, E)$, where $V = \{1, 2, \dots, |V|\}$ represents the finite set of OpenFlow switching elements, and $E \subseteq V \times V$ represents the set of directed physical transmission links. Multiple directed edges may exist between adjacent switching pairs to model redundant trunk aggregates or bundled optical channels.

For each directed edge $e = (u, v) \in E$, the following physical and operational invariants are defined:
\begin{enumerate}
    \item \textbf{Transmission Bandwidth Capacity ($C_e \in \mathbb{R}^+$)}: The maximum line rate of the link in Megabits per second (Mbps). For bidirectional communication, links $e = (u, v)$ and $\bar{e} = (v, u)$ possess symmetric capacity $C_e = C_{\bar{e}}$, though their real-time traffic utilizations are independent.
    \item \textbf{Base Physical Delay ($d_{\text{base}}(e) \in \mathbb{R}^+$)}: The minimum, non-congested transit delay across link $e$, combining physical medium propagation delay and serializer transmission delay for standard Maximum Transmission Unit (MTU = 1500 bytes) frames:
    \begin{equation}
        d_{\text{base}}(e) = d_{\text{prop}}(e) + d_{\text{tx}}(e) = \frac{L_e}{v_{\text{med}}} + \frac{1500 \times 8}{C_e \times 10^6} \quad [\text{seconds}]
    \end{equation}
    where $L_e$ is the fiber/cable physical length in meters and $v_{\text{med}} \approx 2 \times 10^8\text{ m/s}$.
    \item \textbf{Instantaneous Link Utilization ($u_e(t) \in [0.0, 1.0]$)}: The dimensionless fraction of link capacity utilized by aggregate transmitted flows at time $t$:
    \begin{equation}
        u_e(t) = \min\left(1.0, \, \frac{\lambda_e(t)}{C_e}\right)
    \end{equation}
    where $\lambda_e(t)$ is the aggregate traffic arrival rate on link $e$ in Mbps.
\end{enumerate}

\section{The Multi-Commodity Flow Optimization Problem}

\subsection{Continuous Linear Formulation}
Let $\mathcal{K} = \{1, 2, \dots, K\}$ denote the active set of traffic commodities traversing network $G$. Each commodity $k \in \mathcal{K}$ is defined by a source ingress switch $s_k \in V$, a destination egress switch $t_k \in V$, and an instantaneous traffic demand $D_k > 0$.

If traffic flows are infinitely divisible and multi-path splitting is unrestricted, the optimal routing policy solves the classical fractional Multi-Commodity Flow (MCF) optimization problem:
\begin{align}
    \text{Minimize} \quad & \Psi(f) = \sum_{e \in E} \Phi_e\left( \frac{\sum_{k \in \mathcal{K}} f_e^k}{C_e} \right) \label{eq:mcf_objective} \\
    \text{subject to} \quad & \sum_{e \in \delta^+(v)} f_e^k - \sum_{e \in \delta^-(v)} f_e^k = b_v^k \quad \forall v \in V, \, \forall k \in \mathcal{K} \label{eq:mcf_conservation} \\
    & \sum_{k \in \mathcal{K}} f_e^k \le C_e \quad \forall e \in E \label{eq:mcf_capacity} \\
    & f_e^k \ge 0 \quad \forall e \in E, \, \forall k \in \mathcal{K} \label{eq:mcf_nonnegative}
\end{align}
where $f_e^k$ represents the flow rate of commodity $k$ traversing directed edge $e$, $\delta^+(v)$ and $\delta^-(v)$ denote the sets of outgoing and incoming edges incident on vertex $v$, and the divergence vector $b_v^k$ is:
\begin{equation}
    b_v^k = \begin{cases}
        D_k & \text{if } v = s_k \\
        -D_k & \text{if } v = t_k \\
        0 & \text{if } v \in V \setminus \{s_k, t_k\}
    \end{cases}
\end{equation}
The penalty function $\Phi_e(u)$ is a continuous, strictly convex function that models packet queuing delay and buffer overflow risk as link utilization approaches unity.

\subsection{Unsplittable Flow Integer Formulation and Complexity}
In packet-switched computer networks, splitting a single transport-layer TCP flow across multiple paths with disparate latencies induces severe packet reordering. Out-of-order packet arrivals trigger TCP Fast Retransmit and cause the TCP sender to artificially halve its congestion window ($cwnd$), collapsing application throughput.

Consequently, production traffic engineering mandates \textbf{Unsplittable Multi-Commodity Flow (UMCF)}, wherein each commodity $k$ must follow a single, atomic path from source to destination. We introduce binary decision variables:
\begin{equation}
    x_e^k \in \{0, 1\} \quad \forall e \in E, \, \forall k \in \mathcal{K}
\end{equation}
where $x_e^k = 1$ if commodity $k$ traverses edge $e$, and $0$ otherwise. The flow conservation constraint becomes:
\begin{equation}
    \sum_{e \in \delta^+(v)} x_e^k - \sum_{e \in \delta^-(v)} x_e^k = \begin{cases}
        1 & \text{if } v = s_k \\
        -1 & \text{if } v = t_k \\
        0 & \text{otherwise}
    \end{cases} \quad \forall v \in V, \, \forall k \in \mathcal{K}
\end{equation}
and the link capacity constraint becomes:
\begin{equation}
    \sum_{k \in \mathcal{K}} D_k \cdot x_e^k \le C_e \quad \forall e \in E
\end{equation}

\begin{theorem}[$\mathcal{NP}$-Hardness of Unsplittable Traffic Engineering]
The Unsplittable Multi-Commodity Flow problem with capacity constraints is strictly $\mathcal{NP}$-hard.
\end{theorem}

\begin{proof}
We prove $\mathcal{NP}$-hardness by polynomial-time reduction from the classical \textsc{2-Directed Disjoint Paths (2-DDP)} problem, which is proven to be $\mathcal{NP}$-complete \cite{garey1979computers}.

An instance of 2-DDP consists of a directed graph $G = (V, E)$ and two source-terminal pairs $(s_1, t_1)$ and $(s_2, t_2)$. The question is whether there exist two edge-disjoint paths $\mathcal{P}_1$ (from $s_1$ to $t_1$) and $\mathcal{P}_2$ (from $s_2$ to $t_2$) such that $E(\mathcal{P}_1) \cap E(\mathcal{P}_2) = \emptyset$.

We transform this 2-DDP instance into an instance of UMCF:
\begin{enumerate}
    \item Assign unit capacity to all edges: $C_e = 1$ for all $e \in E$.
    \item Define two commodities $\mathcal{K} = \{1, 2\}$ with demands $D_1 = 1$ and $D_2 = 1$.
    \item Set the source-destination pairs as $(s_1, t_1)$ and $(s_2, t_2)$.
\end{enumerate}
In any valid solution to this UMCF instance, for each edge $e \in E$, the capacity constraint requires:
\begin{equation}
    D_1 \cdot x_e^1 + D_2 \cdot x_e^2 = 1 \cdot x_e^1 + 1 \cdot x_e^2 \le 1
\end{equation}
Because $x_e^k \in \{0, 1\}$, it is impossible for both $x_e^1 = 1$ and $x_e^2 = 1$ on any edge $e$. Therefore, the paths selected for commodity 1 and commodity 2 must be strictly edge-disjoint. Thus, a feasible unsplittable flow exists if and only if the 2-DDP instance has a solution. Since the reduction takes linear time, UMCF is $\mathcal{NP}$-hard.
\end{proof}

Because UMCF is $\mathcal{NP}$-hard, computing exact global integer linear programs in real-time under sub-second traffic variations is computationally intractable. This theoretical bottleneck establishes the imperative for an autonomous Deep Reinforcement Learning policy capable of sub-millisecond heuristic inference.

\section{Markov Decision Process (MDP) Formulation}
When a new flow $f = (s, t, \text{demand})$ arrives at ingress switch $s$ destined for egress switch $t$, the SDN controller intercepts the first packet miss and invokes the DRL routing agent. We formalize this decision loop as an MDP:

\subsection{State Space Representation ($\mathcal{S} \in [0.0, 1.0]^{10}$)}
A major barrier in applying reinforcement learning to networking is achieving topological invariance. If the state vector directly encodes raw node IDs or per-link metrics, the neural network structure becomes permanently tied to a specific switch count $|V|$ and link count $|E|$. 

To solve this, we introduce a \textbf{Topologically Normalized 10-Dimensional State Vector} $s_t \in \mathbb{R}^{10}$:

\begin{theorem}[Topological Invariance of State Vector $s_t$]
The state representation $s_t$ is invariant to graph isomorphic relabeling, switch permutations, and absolute graph cardinality $|V|$ and $|E|$.
\end{theorem}

\begin{proof}
Let $G_1 = (V_1, E_1)$ and $G_2 = (V_2, E_2)$ be two arbitrary network graphs. Feature $s_0$ depends strictly on scalar path length $|\mathcal{P}_0|$, scaled by constant $10.0$. Features $s_1$--$s_4$ and $s_9$ depend strictly on scalar link utilization ratios $u(e) \in [0.0, 1.0]$, which are dimensionless quotients of throughput over capacity. Features $s_5$--$s_8$ depend on scalar physical latencies scaled by $50.0\text{ ms}$. None of the features index switch identifiers, port numbers, or matrix dimensions. Therefore, the vector dimensions and semantic meaning remain strictly identical regardless of graph scale, enabling zero-shot model evaluation across arbitrary graphs.
\end{proof}

\subsection{Action Space Formulation ($\mathcal{A} \in \{0, 1, 2, 3\}$)}
Rather than permitting the neural network to output unconstrained next-hop ports at each switch (which creates an exponentially scaling action space and high loop risk), our architecture uses an action space of size $K=4$ representing diversity-aware end-to-end candidate paths:
\begin{equation}
    \mathcal{A} = \{0, 1, 2, 3\}
\end{equation}

Candidate paths are synthesized via Yen's $K$-Shortest Paths algorithm \cite{yen1971finding} augmented with diversity filtering:
\begin{enumerate}
    \item \textbf{Action 0 ($\mathcal{P}_0$)}: Standard Dijkstra Shortest Path (minimum hop count and minimal propagation delay).
    \item \textbf{Action 1 ($\mathcal{P}_1$)}: Second Shortest Simple Path.
    \item \textbf{Action 2 ($\mathcal{P}_2$)}: Edge-Diverse Lateral Bypass Path. Synthesized by selecting the simple path that minimizes edge overlap with $\mathcal{P}_0$:
    \begin{equation}
        \mathcal{P}_2 = \arg\min_{\mathcal{P} \in \mathcal{P}_{\text{cand}} \setminus \{\mathcal{P}_0, \mathcal{P}_1\}} \sum_{e \in \mathcal{P}} \mathbb{I}(e \in \mathcal{P}_0)
    \end{equation}
    \item \textbf{Action 3 ($\mathcal{P}_3$)}: Node-Diverse / Widest Path. Synthesized by selecting the path that maximizes residual bottleneck bandwidth across all intermediate transit nodes disjoint from $\mathcal{P}_0$:
    \begin{equation}
        \mathcal{P}_3 = \arg\max_{\mathcal{P} \in \mathcal{P}_{\text{cand}} \setminus \{\mathcal{P}_0, \mathcal{P}_1, \mathcal{P}_2\}} \min_{e \in \mathcal{P}} \left( C(e) - \text{Throughput}(e) \right)
    \end{equation}
\end{enumerate}

\subsection{Multi-Objective Reward Function}
The scalar reward function balances five competing objectives: hop overhead, propagation and queuing latency, network jitter, packet loss rate, and peak link congestion:
\begin{equation}
    \mathcal{R}(s_t, a_t) = - \Big( w_{\text{hop}} \cdot |\mathcal{P}_a| + w_{\text{lat}} \cdot D(\mathcal{P}_a) + \Phi_{\text{cong}}(U_{\max}) + w_{\text{jit}} \cdot J(\mathcal{P}_a) + w_{\text{loss}} \cdot P_{\text{loss}}(\mathcal{P}_a) \Big)
    \label{eq:multi_objective_reward}
\end{equation}
where $U_{\max} = \max_{e \in \mathcal{P}_a} u(e)$ is the peak bottleneck link utilization on the chosen path, and the calibrated weights are:
\begin{equation}
    w_{\text{hop}} = 0.35, \quad w_{\text{lat}} = 0.06, \quad w_{\text{jit}} = 0.25, \quad w_{\text{loss}} = 0.50
\end{equation}

\section{Derivation of the Asymptotic Congestion Barrier Penalty}
A pivotal theoretical contribution of this project is the formulation of the \textbf{Asymptotic Congestion Barrier Penalty} $\Phi_{\text{cong}}(U_{\max})$. In classical interior-point optimization, barrier functions (such as the Frisch logarithmic barrier $-\mu \ln(C - f)$) prevent optimization variables from violating feasibility boundaries by generating infinite penalty barriers at constraints.

We construct a specialized piecewise continuous barrier function:
\begin{equation}
    \Phi_{\text{cong}}(U_{\max}) = \begin{cases}
        1.5 \cdot U_{\max} & \text{if } U_{\max} \le 0.70 \\[0.5em]
        12.0 \cdot \left( \dfrac{U_{\max}^{1.8}}{\max(0.01, \, 1.02 - U_{\max})} \right) & \text{if } U_{\max} > 0.70
    \end{cases}
    \label{eq:barrier_penalty_formal}
\end{equation}

\subsection{Mathematical Analysis and Gradient Dynamics}
We analyze the first-order derivative of $\Phi_{\text{cong}}$ with respect to bottleneck utilization $u = U_{\max}$ in the barrier regime ($u > 0.70$):
\begin{equation}
    \Phi_{\text{cong}}(u) = 12.0 \cdot \frac{u^{1.8}}{1.02 - u}
\end{equation}
Applying the quotient rule:
\begin{align}
    \frac{d \Phi_{\text{cong}}}{du} &= 12.0 \cdot \frac{1.8 u^{0.8}(1.02 - u) - u^{1.8}(-1)}{(1.02 - u)^2} \nonumber \\
    &= 12.0 \cdot \frac{1.836 u^{0.8} - 1.8 u^{1.8} + u^{1.8}}{(1.02 - u)^2} \nonumber \\
    &= 12.0 \cdot \frac{1.836 u^{0.8} - 0.8 u^{1.8}}{(1.02 - u)^2} > 0 \quad \forall u \in (0.70, 1.0]
\end{align}
Furthermore, the second derivative satisfies:
\begin{equation}
    \frac{d^2 \Phi_{\text{cong}}}{du^2} > 0 \quad \forall u \in (0.70, 1.0]
\end{equation}
confirming that $\Phi_{\text{cong}}(u)$ is strictly convex and monotonically escalating.

\section{Analytical Queuing, Jitter, and Packet Loss Modeling}

\subsection{Path Latency Formulation via Kleinrock's Approximation}
The end-to-end latency $D(\mathcal{P})$ across path $\mathcal{P}$ consists of three additive delay components on each traversed link $e$:
\begin{equation}
    D(\mathcal{P}) = \sum_{e \in \mathcal{P}} \Big( d_{\text{prop}}(e) + d_{\text{tx}}(e) + d_{\text{queue}}(e, u_e) \Big)
\end{equation}
Under Kleinrock's network independence approximation \cite{kleinrock1964communication}, packet arrivals at each internal switch output queue follow Poisson distributions with average rate $\lambda_e$, and packet service times are exponentially distributed with mean service rate $\mu_e = C_e / \bar{L}$, where $\bar{L}$ is the average packet size.

Each link buffer operates as an $M/M/1$ queue. The steady-state average queuing delay is given by:
\begin{equation}
    W_q(e) = \frac{\lambda_e}{\mu_e(\mu_e - \lambda_e)} = \frac{u_e}{\mu_e(1 - u_e)}
\end{equation}
To avoid numerical singularity as $u_e \to 1.0$ and model practical buffer limiters, we formulate the calibrated queuing delay model:
\begin{equation}
    d_{\text{queue}}(e, u_e) = d_{\text{base}}(e) \cdot \left( 0.2 + \frac{0.8}{\max\left(0.05, \, 1.0 - \min(0.95, \, u_e)\right)} \right)
    \label{eq:queuing_delay_formula}
\end{equation}
Under zero load ($u_e = 0$), $d_{\text{queue}} = d_{\text{base}}$. When load reaches $95\%$, the denominator collapses to $0.05$, scaling queuing delay by sixteen-fold to $16.2 \cdot d_{\text{base}}$, accurately modeling real-world buffer congestion.

\subsection{Network Jitter Model (RFC 3393 / RFC 3550)}
Packet delay variation (jitter) measures the statistical variance in one-way end-to-end transit times. Standardized in RFC 3393 \cite{deroo2002ip} and RFC 3550 \cite{schulzrinne2003rtp}, jitter is evaluated via an Exponential Moving Average (EMA) filter:
\begin{equation}
    J_t = J_{t-1} + \frac{|D_t - D_{t-1}| - J_{t-1}}{16}
\end{equation}
In our analytical network queuing engine, jitter volatility is modeled directly as a function of peak path utilization $U_{\max}$:
\begin{equation}
    J(\mathcal{P}) = 0.35 \cdot |\mathcal{P}| + 0.45 \cdot D(\mathcal{P}) \cdot \min\left(5.0, \, \frac{U_{\max}^2}{\max(0.02, \, 1.0 - \min(0.98, \, U_{\max}))}\right)
    \label{eq:jitter_analytical_model}
\end{equation}
When links operate under low load, queue sizes are constant, and jitter remains minimal ($< 1\text{ ms}$). As utilization surpasses $80\%$, bursty packet arrivals cause queue occupancy to oscillate violently, inducing massive jitter spikes.

\subsection{Buffer Overflow Packet Loss Model ($M/M/1/K$)}
In physical OpenFlow switches, output port queues possess a finite buffer capacity of $K$ packets (typically 100 to 1000 packets in commodity hardware). Under the $M/M/1/K$ queuing model, packet loss occurs when an incoming packet arrives while all $K$ buffer slots are occupied.

The stationary distribution of an $M/M/1/K$ queue with traffic intensity $\rho = \lambda / \mu$ yields the blocking probability $P_K$:
\begin{equation}
    P_{\text{loss}} = P_K = \frac{(1 - \rho)\rho^K}{1 - \rho^{K+1}}
\end{equation}
When traffic intensity $\rho = u \le 0.70$ and buffer size $K \ge 100$, the theoretical loss probability is astronomically small ($P_{\text{loss}} < 10^{-6}$). However, when utilization surges beyond $80\%$, microbursts exhaust the remaining buffer slots, triggering drop-tail packet loss. We formulate this empirical reality via:
\begin{equation}
    P_{\text{loss}}(u) = \begin{cases}
        0.01\% & \text{if } u \le 0.70 \\[0.5em]
        0.01\% + 35.0 \cdot \left( \dfrac{u - 0.70}{0.30} \right)^{2.2} & \text{if } u > 0.70
    \end{cases}
    \label{eq:packet_loss_model}
\end{equation}
At $70\%$ load, packet loss is $0.01\%$. At $85\%$ load, loss rises to $7.6\%$. At $100\%$ saturation, packet loss escalates to $35.01\%$, reflecting severe buffer overflow.

\subsection{Jain's Fairness Index Formulation}
To rigorously quantify the global balance of link loads across the entire network topology, we compute Jain's Fairness Index \cite{jain1984quantitative}:
\begin{equation}
    \mathcal{J}(u) = \frac{\left( \sum_{e \in E} u(e) \right)^2}{|E| \cdot \sum_{e \in E} u(e)^2}
    \label{eq:jains_fairness_formula}
\end{equation}

\begin{theorem}[Properties of Jain's Fairness Index]
Jain's Fairness Index satisfies:
\begin{enumerate}
    \item \textbf{Boundedness}: $\frac{1}{|E|} \le \mathcal{J}(u) \le 1.0$.
    \item \textbf{Scale Invariance}: $\mathcal{J}(\alpha u) = \mathcal{J}(u)$ for all scalar multipliers $\alpha > 0$.
    \item \textbf{Continuity}: $\mathcal{J}(u)$ is smooth and continuous for all non-zero link load vectors.
\end{enumerate}
\end{theorem}

\begin{proof}
Let $u = [u_1, \dots, u_{|E|}]^T \in \mathbb{R}^{|E|}$ and let $\mathbf{1} = [1, \dots, 1]^T$. By the Cauchy--Schwarz inequality:
\begin{equation}
    \left( \sum_{e \in E} u(e) \cdot 1 \right)^2 \le \left( \sum_{e \in E} u(e)^2 \right) \left( \sum_{e \in E} 1^2 \right) = |E| \sum_{e \in E} u(e)^2
\end{equation}
Dividing both sides by $|E| \sum_{e \in E} u(e)^2$ yields $\mathcal{J}(u) \le 1.0$. Equality holds if and only if $u(e)$ is identical across all links ($u_1 = u_2 = \dots = u_{|E|}$).

Conversely, if all traffic is concentrated onto a single link $e_1$ such that $u(e_1) = U$ and $u(e_i) = 0$ for all $i \ge 2$, then:
\begin{equation}
    \mathcal{J}(u) = \frac{(U)^2}{|E| \cdot (U^2)} = \frac{1}{|E|}
\end{equation}
Scale invariance follows immediately from homogeneity of degree 2 in both numerator and denominator.
\end{proof}

A high fairness index ($\mathcal{J} \to 1.0$) demonstrates that traffic is balanced evenly across the entire mesh fabric, avoiding destructive core hotspots.

\section{Active Closed-Loop Shadow Reservation and Micro-Burst Damping}
\label{sec:shadow_reservation_math}
In production OpenFlow deployments, switch telemetry statistics are polled periodically at discrete polling intervals $\Delta t_{\text{poll}} \in [1.0, 2.5]\text{ seconds}$ via \texttt{OFPPortStatsRequest}. A critical vulnerability arises when multiple traffic flows arrive within a fraction of this polling window ($t_{\text{arrival}} \ll \Delta t_{\text{poll}}$). In the absence of inter-poll state memory, the controller evaluates identical, stale physical link utilizations $u_e^{\text{phys}}(t)$, which can induce localized micro-herd oscillations.

To mathematically eliminate this latency gap, we formulate an \textbf{Active Closed-Loop Shadow Reservation} mechanism. Let $\Delta \hat{u}_e(t)$ denote the instantaneous virtual load allocated along link $e = (u, v)$ when a flow request with estimated rate $\hat{r}$ is routed along path $\mathcal{P}$:
\begin{equation}
    \Delta \hat{u}_e(t) = \frac{\hat{r}}{C_e} \quad \forall e \in \mathcal{P}
\end{equation}
The cumulative shadow reservation $\hat{u}_e(t)$ evolves according to an exponential continuous decay process governed by half-life parameter $\tau_{\text{half}} \approx 1.5\text{ seconds}$:
\begin{equation}
    \hat{u}_e(t + \delta t) = \hat{u}_e(t) \cdot 2^{-\frac{\delta t}{\tau_{\text{half}}}} + \sum_{k: e \in \mathcal{P}_k} \Delta \hat{u}_e(t_k)
\end{equation}
The \textbf{Effective Link Utilization} $u_e^{\text{eff}}(t)$ observed by the D3QN agent during state extraction is defined as the supremum of physical counter readings and instantaneous shadow reservations:
\begin{equation}
    u_e^{\text{eff}}(t) = \min\left(1.0, \, \max\left( u_e^{\text{phys}}(t), \, u_e^{\text{phys}}(t) + \hat{u}_e(t) \right)\right)
\end{equation}
Whenever an OpenFlow \texttt{OFPPortStatsReply} message is successfully ingested from switch hardware, the physical counter $u_e^{\text{phys}}(t)$ absorbs the true packet transit rate, and the shadow reservation is synchronized ($\hat{u}_e \leftarrow 0$). This ensures continuous, real-time closed-loop damping without waiting for polling ticks.

\section{On-Demand Saturated Core Detour Synthesis}
\label{sec:ondemand_detour_math}
Standard candidate path synthesis via Yen's $K$-Shortest Paths pre-computes $K$ topologically diverse simple paths. However, in extreme traffic regimes where multiple core trunks simultaneously experience heavy queuing saturation ($u_e > \theta = 0.70$), all pre-computed candidate paths $\mathcal{P}_0, \dots, \mathcal{P}_{K-1}$ may share an oversaturated core link.

To guarantee that the D3QN agent is never constrained by a shared-bottleneck trap, we introduce the \textbf{On-Demand Saturated Core Detour Synthesizer}. When the bottleneck load of all primary candidate paths exceeds the critical congestion barrier:
\begin{equation}
    \min_{k \in \{0, 1\}} \left( \max_{e \in \mathcal{P}_k} u_e^{\text{eff}}(t) \right) \ge \theta_{\text{barrier}} = 0.70
\end{equation}
the controller dynamically executes a penalty-weighted constrained shortest path computation over graph $G = (V, E)$ with non-linear congestion penalty edge weights $w_{\text{detour}}(e)$:
\begin{equation}
    w_{\text{detour}}(e) = d_{\text{base}}(e) \cdot \left( 1.0 + \kappa \cdot \max\left(0.0, \, u_e^{\text{eff}}(t) - \theta_{\text{barrier}}\right) \right)
\end{equation}
where $\kappa = 50.0$ is the barrier multiplier. Links operating above $70\%$ saturation incur severe synthetic link costs, forcing the solver to discover alternate lateral bypass detours around the congested core. If the synthesized detour path $\mathcal{P}_{\text{detour}}$ is valid and distinct, it dynamically replaces candidate path $\mathcal{P}_{K-1}$, expanding the action space with an escape route.

\section{Topological Scale Invariance via Receptive Field Mapping}
\label{sec:topological_scale_invariance}
A foundational property of our 10-dimensional state representation is its strict mathematical scale invariance. Rather than supplying the raw node adjacency matrix $\mathbf{A} \in \mathbb{R}^{|V| \times |V|}$ to a large Graph Neural Network (GNN), which would require 5--25~ms per forward pass, our state vector $\mathbf{s}_t$ projects the topological graph dynamics into a localized candidate-path receptive field:
\begin{equation}
    \mathbf{s}_t = \left[ \frac{d_{\text{hop}}}{10.0}, \, U_0^{\text{eff}}, U_1^{\text{eff}}, U_2^{\text{eff}}, U_3^{\text{eff}}, \, \frac{D_0}{50.0}, \frac{D_1}{50.0}, \frac{D_2}{50.0}, \frac{D_3}{50.0}, \, U_{\text{peak}}^{\text{eff}} \right]^T \in [0.0, 1.0]^{10}
\end{equation}
\begin{theorem}[Equivalence to 1-Hop Local Receptive Field]
Let $\mathcal{P}_0, \dots, \mathcal{P}_{K-1}$ denote candidate simple paths between ingress switch $s$ and egress switch $t$. Let $G_{\mathcal{P}} = \bigcup_{k=0}^{K-1} \mathcal{P}_k \subseteq G$ denote the candidate subgraph. The vector $[U_0^{\text{eff}}, \dots, U_{K-1}^{\text{eff}}]^T$ preserves the exact bottleneck cut capacity of subgraph $G_{\mathcal{P}}$. Since $\mathbf{s}_t$ contains no absolute node indices or DPID identifiers, the neural policy mapping $\pi_\theta: [0, 1]^{10} \to \Delta(\mathcal{A})$ is invariant to graph permutation and node relabeling.
\end{theorem}
This guarantees zero-shot transferability across heterogeneous topologies while sustaining inference latencies of less than $0.05\text{ ms}$ ($> 2,400\text{ decisions/second}$).

\section{System Overview and Architectural Decomposition}
The software-defined traffic engineering platform is engineered as a modular, event-driven, microservice-inspired architecture built atop the Ryu SDN framework, PyTorch, and Mininet. The system is decomposed into four tightly coordinated yet logically decoupled subsystems:

\section{OpenFlow 1.3 Control Plane Engine (\texttt{MainController})}
The \texttt{MainController} class (\texttt{controller/main\_controller.py}) inherits from \texttt{ryu.base.app\_manager.RyuApp} and serves as the primary operational coordinator of the SDN control plane.

\subsection{Switch Feature Handshake and Table-Miss Setup}
When an OpenFlow switch initiates a TCP connection to the controller on port 6633/6653, Ryu performs the standard OpenFlow 1.3 protocol handshake:
\begin{enumerate}
    \item The switch and controller exchange \texttt{OFPHello} messages to negotiate the highest mutually supported protocol version (Version 1.3, wire format \texttt{0x04}).
    \item The controller transmits an \texttt{OFPFeaturesRequest}. The switch responds with an \texttt{OFPSwitchFeatures} message detailing its Datapath ID (DPID), buffer capacity, table count, and auxiliary capabilities.
    \item Upon catching \texttt{EventOFPSwitchFeatures}, the controller immediately provisions a default \textbf{Table-Miss Flow Entry} into Flow Table 0.
\end{enumerate}

The Table-Miss rule is installed at Priority 0 with a completely wildcarded match field:
\begin{lstlisting}[language=Python, caption={Table-Miss Entry Installation in MainController}]
@set_ev_cls(ofp_event.EventOFPSwitchFeatures, CONFIG_DISPATCHER)
def switch_features_handler(self, ev):
    datapath = ev.msg.datapath
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser

    # Priority 0 Table-Miss: send unclassified packets to controller
    match = parser.OFPMatch()
    actions = [parser.OFPActionOutput(ofproto.OFPP_CONTROLLER, ofproto.OFPCML_NO_BUFFER)]
    inst = [parser.OFPInstructionActions(ofproto.OFPIT_APPLY_ACTIONS, actions)]
    mod = parser.OFPFlowMod(
        datapath=datapath, priority=0, match=match, instructions=inst
    )
    datapath.send_msg(mod)
\end{lstlisting}
Setting \texttt{max_len=ofproto.OFPCML_NO_BUFFER} instructs the switch to send the complete packet payload to the controller without reserving internal switch buffer space, avoiding buffer leak vulnerabilities in virtual switches.

\subsection{Loop-Free Intelligent ARP Engine without Spanning Tree Protocol}
A classical problem in meshed network architectures is the handling of Address Resolution Protocol (ARP) broadcast frames. In traditional Layer 2 Ethernet networks, broadcast frames are flooded out of every active switch port. In topologies containing physical loops (such as Fat-Tree Clos, Spine-Leaf, or meshed backbones), broadcast flooding triggers catastrophic \textbf{broadcast storms}, where frames multiply exponentially, consuming 100\% of link bandwidth and collapsing switch CPUs within milliseconds.

Traditional networks employ the Spanning Tree Protocol (STP, IEEE 802.1D) to eliminate loops by administratively blocking redundant physical links. However, in adaptive multi-path traffic engineering, administratively disabling redundant links defeats the entire purpose of having parallel bypass paths.

To eliminate broadcast storms while keeping all mesh links active, our \texttt{MainController} implements an \textbf{Intelligent Host-Tracking ARP Engine}:
\begin{enumerate}
    \item \textbf{Selective Ingress Learning}: When an ARP request or reply arrives via \texttt{OFPPacketIn}, the controller inspects the frame. If the frame arrived on an inter-switch trunk link (identified via the live NetworkX topology graph), the controller prunes the binding: host locations are learned \emph{only} when packets arrive on access ports directly attached to end hosts:
    \begin{equation}
        \text{HostLocation}[\text{src\_ip}] = (\text{ingress\_dpid}, \, \text{ingress\_port})
    \end{equation}
    \item \textbf{Target Location Verification}: The controller checks its host tracking table for the target IP address:
    \begin{itemize}
        \item \emph{Known Target}: If the destination host's location $(\text{dst\_dpid}, \text{dst\_port})$ is already known, the controller suppresses broadcast entirely. It formats a directed \texttt{OFPPacketOut} message and transmits the frame \textbf{exclusively via unicast} directly to the specific destination switch and port.
        \item \emph{Unknown Target}: If the destination host has not yet been learned, the controller broadcasts the ARP frame \textbf{strictly across edge access ports} that connect directly to hosts, completely pruning and blocking all inter-switch trunk links.
    \end{itemize}
\end{enumerate}
This intelligent filtering completely eliminates switching loops and broadcast storms, guaranteeing 100\% loop-free Layer 2 resolution across arbitrary cyclic topologies without disabling a single physical link.

\subsection{Telemetry Polling Loop and Active Echo-RTT Probing}
Real-time closed-loop routing requires continuous, accurate telemetry. The \texttt{MainController} spawns an asynchronous Eventlet green thread executing periodically every $\Delta t_{\text{poll}} = 3.0\text{ seconds}$:
\begin{enumerate}
    \item \textbf{Port Statistics Retrieval}: The controller dispatches \texttt{OFPPortStatsRequest} to every connected switch. Switches respond with \texttt{OFPPortStatsReply} containing transmitted packet counts (\texttt{tx\_packets}), received packet counts (\texttt{rx\_packets}), transmitted octets (\texttt{tx\_bytes}), and dropped packets (\texttt{tx\_dropped}).
    \item \textbf{Flow Table Counters}: Issues \texttt{OFPFlowStatsRequest} to inspect individual flow rule durations and byte counts.
    \item \textbf{Active Echo-RTT Latency Probing}: To capture control plane communication latency and detect link degradation, the controller dispatches timestamped \texttt{OFPEchoRequest} frames carrying high-resolution timestamps in their payload:
    \begin{equation}
        \text{Payload} = \text{struct.pack('!d', time.time())}
    \end{equation}
    Upon receiving the corresponding \texttt{OFPEchoReply}, the controller extracts the timestamp and computes the instantaneous round-trip time:
    \begin{equation}
        \text{RTT}_{\text{echo}} = t_{\text{receive}} - t_{\text{echo\_sent}} \quad [\text{seconds}]
    \end{equation}
\end{enumerate}

\section{Telemetry \& Network State Engine (\texttt{StateManager})}
The \texttt{StateManager} class (\texttt{controller/state\_manager.py}) serves as the centralized telemetry data warehouse and network graph abstraction layer.

\subsection{In-Memory NetworkX Topology Representation}
The physical network topology is modeled as a directed graph using \texttt{networkx.DiGraph}. Each node represents an OpenFlow switch DPID; each directed edge $e = (u, v)$ stores operational metadata:
\begin{lstlisting}[language=Python, caption={NetworkX Edge Telemetry Schema in StateManager}]
graph[u][v] = {
    'port': out_port_on_u,
    'capacity': 100.0,            # Max bandwidth in Mbps
    'base_delay': 2.0,            # Propagation delay in ms
    'utilization': 0.0,           # Fraction in [0.0, 1.0]
    'latency': 2.0,               # Real-time queuing latency in ms
    'jitter': 0.5,                # RFC 3393 packet delay variation
    'loss_rate': 0.01             # M/M/1/K drop probability (%)
}
\end{lstlisting}

\subsection{Differential Counter Rate Processing}
Raw OpenFlow port statistics return cumulative byte counters. Because byte counters roll over and reflect historical volume, the \texttt{StateManager} computes instantaneous differential bitrates:
\begin{equation}
    \text{Rate}_{\text{tx}}(e) = \frac{\big(\text{tx\_bytes}(e, t) - \text{tx\_bytes}(e, t - \Delta t)\big) \times 8}{\Delta t \times 10^6} \quad [\text{Mbps}]
\end{equation}
Link utilization is then computed and clamped:
\begin{equation}
    u(e) = \min\left(1.0, \, \max\left(0.0, \, \frac{\text{Rate}_{\text{tx}}(e)}{C(e)}\right)\right)
\end{equation}
An Exponential Moving Average (EMA) smoother with smoothing factor $\alpha_{\text{smooth}} = 0.30$ is applied to dampen high-frequency telemetry noise while remaining sensitive to sudden traffic surges:
\begin{equation}
    \bar{u}(e, t) = \alpha_{\text{smooth}} \cdot u(e, t) + (1 - \alpha_{\text{smooth}}) \cdot \bar{u}(e, t - \Delta t)
\end{equation}

\subsection{Control Plane Message Accounting}
To evaluate control channel overhead (Proposal Objective 5), the \texttt{StateManager} implements fine-grained message accounting, logging the byte overhead of every OpenFlow interaction:
\begin{itemize}
    \item \texttt{packet\_in\_count}: Number of unclassified packet headers forwarded to controller (average overhead: 64 bytes per message).
    \item \texttt{flow\_mod\_count}: Number of FlowMod forwarding rules written to switch TCAM (average overhead: 72 bytes per message).
    \item \texttt{stats\_request\_count}: Number of statistics poll requests dispatched (56 bytes per request).
    \item \texttt{stats\_reply\_count}: Number of multi-part statistics replies ingested (128 bytes per port).
    \item \texttt{controller\_decision\_times}: A fixed-size rolling deque ($N=1000$) capturing the execution time of each neural routing inference in milliseconds.
\end{itemize}

\section{Adaptive Traffic Engineering Engine (\texttt{RoutingModule})}
The \texttt{RoutingModule} class (\texttt{controller/routing\_module.py}) executes the dynamic path selection and rule installation pipeline.

\subsection{Same-Switch Optimization Bypass}
When an incoming flow's source host and destination host are attached to the same edge switch ($\text{src\_dpid} == \text{dst\_dpid}$), path synthesis is completely redundant. The \texttt{RoutingModule} immediately pushes a localized flow rule directing packets from the ingress port to the destination host's access port at Priority 10, bypassing the RL agent entirely and achieving $0.005\text{ ms}$ processing latency.

\subsection{Candidate Path Synthesis and Caching}
For inter-switch flows ($\text{src\_dpid} \ne \text{dst\_dpid}$), candidate paths are synthesized via Yen's $K$-Shortest Paths algorithm ($K=4$). To eliminate the computational overhead of recalculating paths for every individual flow arrival, the module maintains an in-memory cache:
\begin{equation}
    \text{CacheKey} = (\text{src\_dpid}, \, \text{dst\_dpid}) \implies [\mathcal{P}_0, \mathcal{P}_1, \mathcal{P}_2, \mathcal{P}_3]
\end{equation}
When a physical link failure event occurs (\texttt{EventLinkDelete} or \texttt{EventPortStatus}), the cache is instantly invalidated, forcing the re-synthesis of valid topological paths.

\subsection{Multi-Hop Atomic Flow Rule Installation}
Once candidate path $\mathcal{P}_a = (v_0, v_1, \dots, v_m)$ is chosen by the D3QN agent, the controller installs consistent, directional flow entries along every switch in the path:
\begin{lstlisting}[language=Python, caption={Multi-Hop Flow Installation Pipeline in RoutingModule}]
def _install_path(self, path, final_port, eth_dst, ip_src=None, ip_dst=None):
    idle_to = getattr(config, 'FLOW_IDLE_TIMEOUT', 60)
    hard_to = getattr(config, 'FLOW_HARD_TIMEOUT', 120)

    for i in range(len(path)):
        cur_dpid = path[i]
        dp = self.controller.datapaths.get(cur_dpid)
        if not dp: continue

        parser = dp.ofproto_parser
        if i < len(path) - 1:
            next_dpid = path[i+1]
            out_port = self.state_manager.graph[cur_dpid][next_dpid]['port']
        else:
            out_port = final_port

        actions = [parser.OFPActionOutput(out_port)]
        match = parser.OFPMatch(eth_type=0x0800, ipv4_src=ip_src, ipv4_dst=ip_dst)
        self.controller.add_flow(dp, priority=10, match=match, actions=actions,
                                idle_timeout=idle_to, hard_timeout=hard_to)
\end{lstlisting}
Flow rules are configured with an \texttt{idle_timeout} of 60 seconds and a \texttt{hard_timeout} of 120 seconds. This ensures that active flows maintain wire-speed hardware forwarding without recurring controller queries, while inactive rules are autonomously purged from switch TCAM.

\subsection{Weighted Cost Multi-Path (WCMP) via Select Group Tables}
To support fractional multi-path flow dispersion, the \texttt{RoutingModule} provisions OpenFlow 1.3 Select Group tables (\texttt{OFPGT\_SELECT}). The controller computes Softmax distribution weights across candidate paths based on inverse bottleneck link utilization:
\begin{equation}
    \text{Score}(\mathcal{P}_k) = - \left( \beta \cdot \max_{e \in \mathcal{P}_k} u(e) + 0.05 \cdot \sum_{e \in \mathcal{P}_k} d_{\text{base}}(e) \right)
\end{equation}
\begin{equation}
    w_k = \text{round}\left( \frac{\exp(\text{Score}(\mathcal{P}_k))}{\sum_{j=0}^{K-1} \exp(\text{Score}(\mathcal{P}_j))} \times 100 \right)
\end{equation}
where $\beta = 4.0$ is the load sensitivity exponent. An OpenFlow group mod message installs buckets with weights $w_k$. Switch hardware hashes packet 5-tuples to assign flows to buckets proportional to their assigned weights, enabling adaptive multi-path load distribution.

\subsection{Sub-Millisecond Fast Failover (FF) Hardware Protection}
For mission-critical link resiliency, the platform provisions OpenFlow Fast Failover groups (\texttt{OFPGT\_FF}):
\begin{itemize}
    \item \textbf{Bucket 1 (Primary Action)}: Directs packets to primary shortest path $\mathcal{P}_0$ with \texttt{watch\_port = port\_primary}.
    \item \textbf{Bucket 2 (Backup Action)}: Directs packets to edge-disjoint lateral bypass path $\mathcal{P}_2$ with \texttt{watch\_port = port\_backup}.
\end{itemize}
When a fiber cut or physical switch port failure occurs, switch hardware detects the loss of carrier signal and autonomously diverts subsequent packets to Bucket 2 within $2.1\text{ ms}$, achieving carrier-grade resilience without waiting for an OpenFlow controller round-trip cycle.

\subsection{Decoupled Asynchronous Training Architecture}
A critical engineering breakthrough in our platform is the decoupling of neural network training from the OpenFlow event loop. In naive implementations, running PyTorch backpropagation synchronously inside the \texttt{OFPPacketIn} handler blocks the entire controller, causing packet processing delays of 50--200~ms.

We decouple the training pipeline into a dedicated background daemon thread:
\begin{itemize}
    \item \textbf{Online Packet Handling Thread}: Executes neural forward inference only. Forward inference requires less than $0.05\text{ ms}$, allowing the controller to handle thousands of concurrent packet-in events per second.
    \item \textbf{Background Training Worker}: Runs asynchronously in a continuous loop every 2.0 seconds. It samples mini-batches from the PER buffer, computes Huber loss, updates neural gradients, and performs Polyak target synchronization without impacting packet-forwarding latency.
\end{itemize}

\section{Hierarchical TCAM-Conscious Flow Table Allocation}
\label{sec:tcam_conservation_architecture}
A critical scalability constraint in commodity OpenFlow hardware switches (e.g., Broadcom StrataXGS / Trident chipsets) is the finite size of Ternary Content-Addressable Memory (TCAM), which typically accommodates only 2,000 to 8,000 flow rules. Installing fine-grained 5-tuple matching rules (\texttt{eth\_src, eth\_dst, ip\_src, ip\_dst, ip\_proto}) for every microflow in high-density datacenters risks rapid TCAM exhaustion and controller table-full errors.

To overcome this hardware barrier, the platform implements a \textbf{Hierarchical TCAM-Conscious Flow Allocation Policy} in \texttt{controller/routing\_module.py}:
\begin{enumerate}
    \item \textbf{Mice / Standard Microflow Aggregation}: Short-lived, low-bandwidth flows ($r < 5.0\text{ Mbps}$) carry little congestion risk. For these flows, the controller installs wildcard rules matching aggregated destination IP subnets or MAC bindings with a standard priority of 10 and an aggressive \texttt{idle\_timeout} of 15 seconds. Dead microflows are purged rapidly, preserving hardware TCAM capacity.
    \item \textbf{Elephant Flow Splitting and Dynamic Pinning}: When a flow's transmission rate exceeds the elephant threshold ($r \ge 5.0\text{ Mbps}$) or is explicitly tagged, the controller installs an exact 5-tuple flow entry with a higher priority of 20 and an extended \texttt{idle\_timeout} of 60 seconds. This pins the high-volume elephant flow to the optimal DRL candidate bypass path, preventing packet reordering and congestion buildup.
    \item \textbf{Hardware Group Table Offloading (WCMP)}: On multi-path fabrics, the controller leverages OpenFlow 1.3 \texttt{OFPGT\_SELECT} Group Tables. Multiple incoming flows hash across pre-installed group action buckets matching calculated Weighted Cost Multi-Path (WCMP) distribution ratios, reducing required flow table entries from $O(|F|)$ down to $O(|V|)$.
\end{enumerate}
This hierarchical allocation scheme reduces physical switch TCAM rule footprint by over $85\%$, ensuring viable deployment on resource-constrained commercial switching silicon.

\subsection{The Role of Layer Normalization in Network Control Loops}
In computer network control environments, link loads, queuing delays, and packet dropouts exhibit extreme spatial and temporal volatility. An elephant flow arrival can cause a link's measured utilization to jump from $0.05$ to $0.98$ within a single polling interval. In standard unnormalized networks, such sharp input shifts cause internal covariate shift, resulting in exploding gradients that destabilize training or collapse Q-values into local minima.

To ensure numerical stability, we incorporate \textbf{Layer Normalization} (\texttt{nn.LayerNorm}) \cite{ba2016layer} after each dense linear projection. Unlike Batch Normalization (which computes statistics across mini-batch samples and fails during single-sample real-time inference), Layer Normalization standardizes activations across the channel dimension for each transition independently:
\begin{equation}
    \mu_L = \frac{1}{H} \sum_{i=1}^H x_i, \quad \sigma_L^2 = \frac{1}{H} \sum_{i=1}^H (x_i - \mu_L)^2
\end{equation}
\begin{equation}
    \text{LN}(x) = \frac{x - \mu_L}{\sqrt{\sigma_L^2 + \epsilon}} \odot \gamma + \beta
\end{equation}
where $H$ is the hidden layer dimension, and $\gamma, \beta \in \mathbb{R}^H$ are learnable affine parameters. Layer Normalization guarantees that activations remain strictly zero-centered and unit-variance, allowing smooth gradient descent even during violent traffic surges.

\subsection{Mathematical Proof of Dueling Identifiability}
A fundamental challenge in decomposing action values into value $V(s)$ and advantage $A(s, a)$ is \emph{unidentifiability}. Given $Q(s, a) = V(s) + A(s, a)$, adding an arbitrary constant $c$ to $V(s)$ while subtracting $c$ from $A(s, a)$ produces the exact same $Q$-value, preventing unique parameter recovery.

\begin{theorem}[Identifiability of Mean-Subtracted Dueling Network]
The aggregation formula:
\begin{equation}
    Q(s, a; \theta, \alpha, \beta) = V(s; \theta, \beta) + \left( A(s, a; \theta, \alpha) - \frac{1}{|\mathcal{A}|} \sum_{a' \in \mathcal{A}} A(s, a'; \theta, \alpha) \right)
    \label{eq:dueling_identifiability_proof}
\end{equation}
guarantees unique identifiability such that $V(s)$ represents the arithmetic mean of optimal action values across the action space.
\end{theorem}

\begin{proof}
Let $\bar{A}(s) = \frac{1}{|\mathcal{A}|} \sum_{a' \in \mathcal{A}} A(s, a')$. Summing Equation~\ref{eq:dueling_identifiability_proof} over all actions $a \in \mathcal{A}$:
\begin{align}
    \sum_{a \in \mathcal{A}} Q(s, a) &= \sum_{a \in \mathcal{A}} \left( V(s) + A(s, a) - \bar{A}(s) \right) \nonumber \\
    &= |\mathcal{A}| \cdot V(s) + \sum_{a \in \mathcal{A}} A(s, a) - |\mathcal{A}| \cdot \bar{A}(s) \nonumber \\
    &= |\mathcal{A}| \cdot V(s) + |\mathcal{A}| \bar{A}(s) - |\mathcal{A}| \bar{A}(s) \nonumber \\
    &= |\mathcal{A}| \cdot V(s)
\end{align}
Dividing both sides by $|\mathcal{A}|$:
\begin{equation}
    V(s) = \frac{1}{|\mathcal{A}|} \sum_{a \in \mathcal{A}} Q(s, a)
\end{equation}
Thus, $V(s)$ is uniquely identified as the average value of all candidate actions in state $s$, and the advantage terms $A(s, a) - \bar{A}(s)$ uniquely represent zero-mean deviations, establishing mathematical identifiability.
\end{proof}

\section{Binary SumTree Prioritized Experience Replay (PER)}
To overcome the limitations of uniform replay sampling, the \texttt{PrioritizedReplayBuffer} (\texttt{agent/prioritized\_replay.py}) implements an iterative binary \textbf{SumTree} data structure supporting $O(\log N)$ sampling and priority updates.

\subsection{Array-Based Binary SumTree Data Structure}
A binary SumTree is a complete binary tree where:
\begin{itemize}
    \item Each leaf node stores the priority $p_i$ of an individual transition tuple $e_i = (s_i, a_i, r_i, s_{i+1})$.
    \item Each internal node stores the exact sum of the priorities of its two child subtrees:
    \begin{equation}
        \text{tree}[\text{parent}] = \text{tree}[\text{left\_child}] + \text{tree}[\text{right\_child}]
    \end{equation}
    \item The root node ($\text{tree}[0]$) stores the grand sum of all transition priorities in memory:
    \begin{equation}
        \text{tree}[0] = \sum_{k=1}^N p_k
    \end{equation}
\end{itemize}

For a buffer capacity of $N = 5,000$ transitions, the SumTree is allocated as a single, contiguous 1D NumPy array of size $2N - 1 = 9,999$ elements:
\begin{itemize}
    \item Internal parent nodes occupy indices $0$ through $N - 2$.
    \item Leaf nodes occupy indices $N - 1$ through $2N - 2$.
    \item For any internal node at index $i$:
    \begin{equation}
        \text{left\_child}(i) = 2i + 1, \quad \text{right\_child}(i) = 2i + 2
    \end{equation}
    \item For any child node at index $j > 0$:
    \begin{equation}
        \text{parent}(j) = \lfloor (j - 1) / 2 \rfloor
    \end{equation}
\end{itemize}

\subsection{Sampling and Update Algorithms in Formal Pseudocode}
Sampling a mini-batch of size $B=32$ transitions proceeds by partitioning the range $[0, \text{tree}[0]]$ into $B$ equal intervals:
\begin{equation}
    I_k = \left[ k \cdot \frac{\text{tree}[0]}{B}, \, (k + 1) \cdot \frac{\text{tree}[0]}{B} \right) \quad \forall k \in \{0, 1, \dots, B-1\}
\end{equation}
A uniform random value $v_k \sim \mathcal{U}(I_k)$ is drawn from each interval, and the tree is traversed from the root downward to locate the corresponding leaf in exactly $\lceil \log_2 N \rceil = 13$ steps. Algorithm~\ref{alg:sumtree_sampling} and Algorithm~\ref{alg:sumtree_update} detail the iterative, non-recursive implementations.

\begin{algorithm}[htbp]
\caption{Iterative Non-Recursive Binary SumTree Retrieval}
\label{alg:sumtree_sampling}
\begin{algorithmic}[1]
\REQUIRE SumTree array $\text{tree}$ of size $2N - 1$, search value $v \in [0, \text{tree}[0]]$
\ENSURE Leaf index $\text{tree\_idx}$, priority value $p$, and data pointer $\text{data\_idx}$
\STATE $\text{idx} \gets 0$ \COMMENT{Start at root node}
\WHILE{$\text{idx} < N - 1$} \COMMENT{Loop until reaching a leaf node}
    \STATE $\text{left} \gets 2 \cdot \text{idx} + 1$
    \STATE $\text{right} \gets \text{left} + 1$
    \IF{$v \le \text{tree}[\text{left}]$}
        \STATE $\text{idx} \gets \text{left}$
    \ELSE
        \STATE $v \gets v - \text{tree}[\text{left}]$
        \STATE $\text{idx} \gets \text{right}$
    \ENDIF
\ENDWHILE
\STATE $\text{data\_idx} \gets \text{idx} - (N - 1)$
\RETURN $\text{idx}, \, \text{tree}[\text{idx}], \, \text{data\_idx}$
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[htbp]
\caption{Iterative Non-Recursive Binary SumTree Priority Update}
\label{alg:sumtree_update}
\begin{algorithmic}[1]
\REQUIRE SumTree array $\text{tree}$, leaf index $\text{tree\_idx}$, new priority $p_{\text{new}}$
\ENSURE Updated prefix sums propagated from leaf to root
\STATE $\Delta \gets p_{\text{new}} - \text{tree}[\text{tree\_idx}]$ \COMMENT{Compute priority differential}
\STATE $\text{tree}[\text{tree\_idx}] \gets p_{\text{new}}$
\STATE $\text{idx} \gets \text{tree\_idx}$
\WHILE{$\text{idx} > 0$} \COMMENT{Propagate differential up to root}
    \STATE $\text{idx} \gets \lfloor (\text{idx} - 1) / 2 \rfloor$ \COMMENT{Move to parent}
    \STATE $\text{tree}[\text{idx}] \gets \text{tree}[\text{idx}] + \Delta$
\ENDWHILE
\end{algorithmic}
\end{algorithm}

\subsection{Importance Sampling Weight Annealing}
Prioritized sampling introduces bias because transitions with high TD error are sampled more frequently than their true empirical distribution. We correct this bias using Importance Sampling (IS) weights:
\begin{equation}
    w_i = \left( \frac{1}{N} \cdot \frac{1}{P(i)} \right)^\beta = \left( \frac{\text{tree}[0]}{N \cdot p_i^\alpha} \right)^\beta
\end{equation}
Weights are normalized by the maximum weight in the mini-batch:
\begin{equation}
    \tilde{w}_i = \frac{w_i}{\max_j w_j} \in (0.0, 1.0]
\end{equation}
The parameter $\beta$ controls the degree of correction. Early in training, gradient direction is noisy, so partial correction ($\beta_0 = 0.4$) accelerates discovery. As policy convergence approaches, full correction ($\beta \to 1.0$) is essential for asymptotic unbiased convergence:
\begin{equation}
    \beta(t) = \min\left(1.0, \, \beta_0 + t \cdot \frac{1.0 - \beta_0}{T_{\text{max}}}\right)
\end{equation}

\section{Polyak Soft Target Updates vs. Periodic Hard Copies}
In standard DQN \cite{mnih2015human}, target network parameters $\theta^-$ are updated via periodic hard copies every $C$ steps ($\theta^- \gets \theta$). In network traffic engineering, hard updates trigger sudden, violent shifts in target values $Y_t$, causing transient routing oscillations and policy collapse immediately following each synchronization.

To eliminate target instability, our agent implements \textbf{Polyak Soft Target Updates} \cite{lillicrap2015continuous}. After every gradient backpropagation step, target parameters are blended continuously toward online parameters:
\begin{equation}
    \theta^- \gets \tau \cdot \theta + (1 - \tau) \cdot \theta^-
    \label{eq:polyak_update}
\end{equation}
where $\tau = 0.005$ is the soft tracking rate. Polyak averaging acts as an exponential low-pass filter over parameter trajectories, ensuring that target Q-values evolve smoothly and monotonically.

\section{Huber Loss vs. Mean Squared Error}
Standard Mean Squared Error (MSE), $\mathcal{L}_{\text{MSE}}(\delta) = \delta^2$, has a quadratic gradient with respect to TD error: $\nabla_\theta \mathcal{L} = 2 \delta \nabla_\theta Q$. When sudden traffic bursts occur, the instantaneous TD error $\delta_i$ can exceed $50.0$, generating massive gradients ($2 \times 50 = 100$) that destabilize the Adam optimizer.

We employ the \textbf{Smooth L1 (Huber) Loss Function}:
\begin{equation}
    \mathcal{L}_{\text{Huber}}(\delta) = \begin{cases}
        0.5 \cdot \delta^2 & \text{if } |\delta| \le 1.0 \\[0.5em]
        |\delta| - 0.5 & \text{otherwise}
    \end{cases}
\end{equation}
whose gradient is:
\begin{equation}
    \frac{\partial \mathcal{L}_{\text{Huber}}}{\partial \delta} = \begin{cases}
        \delta & \text{if } |\delta| \le 1.0 \\
        \text{sign}(\delta) & \text{otherwise}
    \end{cases}
\end{equation}
For errors exceeding $1.0$, the gradient magnitude is strictly capped at $\pm 1.0$. This linear clipping prevents exploding gradients, guaranteeing robust convergence under extreme network traffic volatility.

\section{Complete End-to-End D3QN-PER Training Algorithm}
Algorithm~\ref{alg:d3qn_complete_loop} formalizes the complete training loop executed across the 1,000 curriculum episodes.

\begin{algorithm}[htbp]
\caption{Complete D3QN-PER Adaptive Traffic Engineering Training Pipeline}
\label{alg:d3qn_complete_loop}
\begin{algorithmic}[1]
\REQUIRE Mininet network topology $G = (V, E)$, episodes $M = 1000$, steps per episode $T = 30$, batch size $B = 32$, replay capacity $N = 5000$, learning rate $\alpha = 0.001$, soft update rate $\tau = 0.005$, discount factor $\gamma = 0.95$
\ENSURE Optimized D3QN weights $\theta^*$
\STATE Initialize online network parameters $\theta$ randomly; target network $\theta^- \gets \theta$
\STATE Initialize SumTree replay buffer $\mathcal{D}$ with capacity $N$, priorities $\alpha = 0.6$, $\beta_0 = 0.4$
\FOR{episode $m = 1$ \TO $M$}
    \STATE Calculate curriculum exploration rate $\epsilon(m)$ and injection stress profile
    \STATE Reset network link states; observe initial state $s_0 \in \mathbb{R}^{10}$
    \FOR{step $t = 1$ \TO $T$}
        \STATE Sample $r \sim \mathcal{U}(0, 1)$
        \IF{$r < \epsilon(m)$}
            \STATE Select random candidate path action $a_t \sim \mathcal{U}(\{0, 1, 2, 3\})$
        \ELSE
            \STATE Select greedy action $a_t = \arg\max_{a} Q(s_t, a; \theta)$ via forward pass
        \ENDIF
        \STATE Route flow along path $\mathcal{P}_{a_t}$; accumulate link traffic
        \STATE Calculate multi-objective reward $r_t = \mathcal{R}(s_t, a_t)$ via Equation~\ref{eq:multi_objective_reward}
        \STATE Observe subsequent state $s_{t+1} \in \mathbb{R}^{10}$
        \STATE Store transition $(s_t, a_t, r_t, s_{t+1})$ in SumTree $\mathcal{D}$ with max priority $p_{\text{max}}$
        \IF{$|\mathcal{D}| \ge B$}
            \STATE Sample mini-batch of $B$ transitions using Algorithm~\ref{alg:sumtree_sampling}
            \STATE Compute Importance Sampling weights $\tilde{w}_i$ via Equation~\ref{eq:per_is_weights}
            \FOR{each sample $i \in \{1, \dots, B\}$}
                \STATE $a^* \gets \arg\max_{a'} Q(s'_{i}, a'; \theta)$ \COMMENT{Action selection via online network}
                \STATE $Y_i \gets r_i + \gamma Q(s'_{i}, a^*; \theta^-)$ \COMMENT{Action evaluation via target network}
                \STATE $\delta_i \gets Q(s_i, a_i; \theta) - Y_i$ \COMMENT{Compute TD error}
                \STATE Update transition priority in SumTree: $p_i \gets (|\delta_i| + 10^{-5})^\alpha$
            \ENDFOR
            \STATE Compute weighted loss: $\mathcal{L} = \frac{1}{B}\sum_{i=1}^B \tilde{w}_i \cdot \mathcal{L}_{\text{Huber}}(\delta_i)$
            \STATE Execute Adam backpropagation: $\theta \gets \theta - \alpha \nabla_\theta \mathcal{L}$
            \STATE Execute Polyak soft update: $\theta^- \gets \tau \theta + (1 - \tau) \theta^-$
        \ENDIF
        \STATE $s_t \gets s_{t+1}$
    \ENDFOR
\ENDFOR
\RETURN $\theta^* \gets \theta$
\end{algorithmic}
\end{algorithm}

\subsection{Hierarchical Tree Fabric (7 Switches, 8 Hosts)}
The Hierarchical Tree topology represents the classical 3-tier enterprise campus design:
\begin{itemize}
    \item \textbf{Core Tier}: Switch $s_1$ acts as the single central transit router.
    \item \textbf{Aggregation Tier}: Switches $s_2$ and $s_3$ aggregate traffic from edge switches.
    \item \textbf{Edge Tier}: Switches $s_4, s_5, s_6, s_7$ connect directly to end hosts $h_1$ through $h_8$.
    \item \textbf{Lateral Cross-Links}: Redundant horizontal bypass links connect adjacent edge switches ($s_4 \leftrightarrow s_6$ and $s_5 \leftrightarrow s_7$) with $100\text{ Mbps}$ capacity.
\end{itemize}
Under traditional shortest-path routing, all inter-pod traffic is funneled through core switch $s_1$, creating severe core bottlenecks while the lateral cross-links remain completely unutilized. The Hierarchical Tree provides a clean testbed for verifying lateral link offloading.

\subsection{Fat-Tree Clos Fabric ($k=4$, 20 Switches, 16 Hosts)}
The Fat-Tree topology \cite{al2008scalable} implements a multi-stage Clos network widely deployed in modern private and public cloud data centers:
\begin{itemize}
    \item \textbf{Pod Architecture}: Four distinct pods ($k=4$). Each pod contains two aggregation switches and two edge switches.
    \item \textbf{Core Tier}: Four centralized core switches interconnected with all aggregation switches:
    \begin{equation}
        N_{\text{core}} = (k/2)^2 = (4/2)^2 = 4 \text{ Core Switches}
    \end{equation}
    \item \textbf{Edge and Host Connectivity}: Eight edge switches connect to sixteen bare-metal hosts ($h_1$ through $h_{16}$).
    \item \textbf{Bisection Bandwidth}: Possesses full bisection bandwidth: any arbitrary bisection cut intersects 16 full-rate links.
\end{itemize}
Because multiple parallel paths exist between any two pods, the Fat-Tree fabric presents the ideal environment to evaluate multi-path load balancing and elephant flow collision avoidance.

\subsection{Abilene US Backbone Network (12 Switches, 8 Hosts)}
The Abilene network represents the high-speed continental backbone of the Internet2 nationwide research network across the continental United States:
\begin{itemize}
    \item \textbf{Topological Structure}: 12 switches interconnected by 30 directed transmission links spanning Seattle, Sunnyvale, Los Angeles, Denver, Kansas City, Houston, Chicago, Indianapolis, Atlanta, Washington DC, and New York.
    \item \textbf{Asymmetric Propagation Delays}: Unlike local data centers (where delay is negligible), Abilene links exhibit real-world geographic propagation delays ranging from $2.0\text{ ms}$ (Chicago to Indianapolis) to $8.5\text{ ms}$ (Seattle to Sunnyvale).
\end{itemize}
Abilene provides the critical benchmark for evaluating the trade-off between detour path length (WAN propagation latency) and core link queuing delay.

\subsection{NSFNet Continental Mesh (14 Switches, 8 Hosts)}
The National Science Foundation Network (NSFNet) was the historic foundation of the modern Internet. It represents an irregular, non-symmetric continental mesh:
\begin{itemize}
    \item \textbf{Topological Structure}: 14 switches interconnected by 42 directed transmission links.
    \item \textbf{Node Degree Diversity}: Switch node degrees range from 2 (e.g., edge transit nodes) up to 4 (e.g., highly connected central transit hubs).

\subsection{Spine-Leaf Data Center Fabric (12 Switches, 16 Hosts)}
The Spine-Leaf architecture represents the modern state-of-the-art for hyperscale cloud data center fabrics (e.g., AWS, Azure, Google Cloud):
\begin{itemize}

    \item \textbf{Leaf Tier}: 8 access leaf switches ($s_5$ through $s_{12}$), each directly attached to compute servers.

Under classical single-path routing, a leaf pair picks a single spine, leaving three-quarters of the fabric bandwidth wasted. The Spine-Leaf fabric rigorously evaluates the agent's ability to achieve 100\% fabric dispersion.

\section{Synthetic Traffic Generation Engine}
Realistic workload modeling is essential to prevent reinforcement learning agents from overfitting to trivial static traffic patterns. The synthetic traffic generation engine (\texttt{simulate\_live\_traffic.py} and \texttt{topology/traffic\_generator.sh}) implements a multi-tier stochastic traffic injection framework.

\subsection{Poisson Process for Background Mice Flows}
Background transactional traffic (DNS queries, HTTP micro-requests, RPC handshakes) is modeled as an independent Poisson arrival process. The probability of $k$ flow arrivals occurring within time interval $t$ is:
\begin{equation}
    \mathbb{P}(N(t) = k) = \frac{(\lambda_{\text{mice}} \cdot t)^k \cdot e^{-\lambda_{\text{mice}} t}}{k!}
\end{equation}
where $\lambda_{\text{mice}} = 15.0\text{ flows/second}$. Each mice flow is allocated a modest bandwidth demand uniformly sampled:
\begin{equation}
    D_{\text{mice}} \sim \mathcal{U}(3.0\text{ Mbps}, \, 8.0\text{ Mbps})
\end{equation}
Mice flows persist for short durations $T_{\text{mice}} \sim \mathcal{U}(1.5\text{s}, \, 4.0\text{s})$ before terminating and releasing link buffer capacity.

\subsection{Heavy-Tailed Pareto Distribution for Elephant Microbursts}
Bulk data transfers, database backups, and VM live migrations exhibit heavy-tailed size distributions, where a tiny fraction of flows account for the vast majority of transmitted octets. We model elephant flows via the classical \textbf{Bounded Pareto Distribution}:
\begin{equation}
    f(x; \alpha, x_m, x_M) = \frac{\alpha \cdot x_m^\alpha \cdot x^{-\alpha - 1}}{1 - (x_m / x_M)^\alpha} \quad \text{for } x_m \le x \le x_M
\end{equation}
where:
\begin{itemize}
    \item Shape parameter $\alpha = 1.2$ reflects heavy-tailed Internet traffic measurements.
    \item Minimum flow demand $x_m = 35.0\text{ Mbps}$.
    \item Maximum flow demand $x_M = 85.0\text{ Mbps}$.
\end{itemize}
Elephant flows are injected between diagonal edge switches across pod boundaries, persisting for $T_{\text{elephant}} \sim \mathcal{U}(10.0\text{s}, \, 25.0\text{s})$, designed to aggressively saturate standard shortest paths.

\subsection{Spatial Hotspot Clustered Surges}
In enterprise campus and multi-tenant networks, traffic frequently exhibits spatial locality (e.g., sudden video broadcast from a conference hall, distributed MapReduce shuffle phase). We model this via spatial hotspot clustering:
\begin{equation}
    \mathbb{P}(\text{Source} = v_i, \, \text{Dest} = v_j) = \begin{cases}
        0.75 \cdot \frac{1}{|V_{\text{hotspot}}|^2} & \text{if } v_i, v_j \in V_{\text{hotspot}} \\[0.5em]
        0.25 \cdot \frac{1}{|V \setminus V_{\text{hotspot}}|^2} & \text{otherwise}
    \end{cases}
\end{equation}
where $V_{\text{hotspot}}$ represents a localized cluster of edge switches (e.g., switches $s_4$ and $s_5$).

\subsection{Targeted Core Jamming Stress Model}
To stress-test emergency anti-congestion rerouting, the engine implements targeted core link pre-loading. Prior to injecting measurement flows, central transit links are pre-loaded to $85\%$--$98\%$ utilization by generating persistent synthetic saturation streams:
\begin{equation}
    \text{PreLoad}(e_{\text{core}}) \sim \mathcal{U}(0.85 \cdot C_e, \, 0.98 \cdot C_e)
\end{equation}
This forces the RL agent to immediately detect the asymptotic barrier penalty $\Phi_{\text{cong}}$ and dynamically steer new arrivals onto lateral bypass paths.

\subsection{Evaluated Routing Paradigms}

\begin{enumerate}
    \item \textbf{OSPF (RFC 2328)}: Standard shortest-path routing based on administrative capacity weights ($w_e = \max(1, \text{round}(10^8 / C_e))$).
    \item \textbf{Dijkstra SPF}: Pure hop-count shortest-path first algorithm.
    \item \textbf{Equal-Cost Multi-Path (ECMP)}: 5-tuple hash-based packet distribution across equal-cost shortest paths.
    \item \textbf{Widest Shortest Path (WSP / CSPF)}: Residual bottleneck bandwidth tie-breaking heuristic.
    \item \textbf{Greedy Least Loaded Routing (LLR)}: Instantaneous utilization minimization heuristic.
    \item \textbf{D3QN Adaptive Traffic Engineering (Ours)}: Topologically normalized Dueling Double Deep Q-Network with binary SumTree PER and asymptotic barrier rewards.
\end{enumerate}

\subsection{Traffic Injection and Closed-Loop Accounting}
For each benchmark trial:
\begin{itemize}
    \item 150 independent unicast flows are injected into the network.
    \item Ingress and egress switch endpoints are drawn randomly from available access switches.
    \item Flow bandwidth demands are drawn from the mixed workload generator (Poisson mice flows + bursty Pareto elephant flows).
    \item Flows accumulate bandwidth on traversed link buffers, incrementing real-time utilization $u(e)$.
    \item Flows expire after calibrated durations, releasing capacity in a closed-loop dynamic state machine.
\end{itemize}

\section{Critical Theoretical Analysis and Engineering Trade-Offs}
In accordance with the highest standards of academic inquiry expected by graduation examination committees, this section presents an unsparing, objective critique of the system's operational boundaries, architectural trade-offs, and empirical edge cases.

\subsection{The Herd Behavior Failure in Dynamic Heuristics}
In closed-loop network environments where flows persist over time, classical dynamic greedy heuristics (\textbf{Widest Shortest Path - WSP} and \textbf{Least Loaded Routing - LLR}) exhibited severe, destructive herd behavior oscillations:
\begin{itemize}
    \item On the Fat-Tree Clos fabric, greedy heuristics repeatedly routed multiple consecutive incoming flows onto the single instantaneous lowest-loaded link, driving that link into sudden $76.4\%$ saturation before the next telemetry polling window.
    \item The D3QN agent maintained an average peak utilization of just \textbf{$23.29\%$}, while delivering lower latency ($7.00\text{ ms}$) and lower packet loss ($0.012\%$).
\end{itemize}

\subsubsection{Theoretical Root Cause}
Greedy heuristics make myopic $O(1)$ decisions based solely on instantaneous metrics at time $t$:
\begin{equation}
    a_t^{\text{Greedy}} = \arg\min_a \left( \max_{e \in \mathcal{P}_a} u(e, t) \right)
\end{equation}
Because OpenFlow telemetry polling occurs at discrete time intervals ($\Delta t_{\text{poll}} = 3.0\text{ seconds}$), any flows arriving during that 3-second window observe the exact same utilization vector $u(e, t)$. Every flow independently picks the same link, causing violent load spikes.

In contrast, our D3QN agent evaluates long-term expected returns:
\begin{equation}
    Q(s_t, a_t) = \mathbb{E}\left[ \sum_{k=0}^\infty \gamma^k r_{t+k} \;\middle|\; s_t, a_t \right]
\end{equation}
Because the state-value stream $V(s)$ and advantage stream $A(s, a)$ are trained under discounted future rewards ($\gamma = 0.95$) with the non-linear asymptotic barrier penalty $\Phi_{\text{cong}}$, the neural network anticipates that directing multiple flows onto a single link will rapidly degrade future states. The policy naturally diffuses flows across diverse candidate paths, inherently suppressing herd behavior oscillations.

\subsection{The WAN Detour Latency Penalty and Propagation Dilemma}
In Scenario 4 (where core link delay was degraded), D3QN exhibited slightly higher path latency than Dijkstra SPF on the continental Abilene network ($22.85\text{ ms}$ vs. $23.38\text{ ms}$) when avoiding core bottlenecks.

\subsubsection{Theoretical Root Cause}
This is a direct, deliberate consequence of the multi-objective reward function weighting:
\begin{equation}
    \mathcal{R} = - \Big( 0.35 \cdot \text{hops} + 0.06 \cdot D + \Phi_{\text{cong}}(U_{\max}) + 0.25 \cdot J + 0.50 \cdot P_{\text{loss}} \Big)
\end{equation}
On Wide Area Networks (WANs), perimeter links span thousands of kilometers of physical fiber (e.g., routing traffic from Chicago to Sunnyvale via Atlanta and Houston). The physical propagation delay across perimeter links is substantial ($d_{\text{prop}} \approx 20\text{--}30\text{ ms}$).

When a central core link experiences moderate congestion ($u \approx 75\%$), the D3QN agent faces a fundamental trade-off:
\begin{enumerate}
    \item Stay on the core link: incur low physical propagation delay ($10\text{ ms}$) but suffer queuing delay ($15\text{ ms}$), buffer jitter ($5\text{ ms}$), and drop risk ($3\%$). Total perceived cost is high due to $\Phi_{\text{cong}}$ and $P_{\text{loss}}$.
    \item Detour around perimeter: incur zero queuing delay and zero packet loss, but pay a fixed physical speed-of-light propagation penalty ($25\text{ ms}$).
\end{enumerate}
The D3QN agent correctly prioritizes congestion avoidance and zero packet dropouts over raw speed-of-light propagation delay. This trade-off is optimal for throughput-intensive TCP applications, as TCP throughput collapses exponentially under packet loss, whereas moderate propagation latency merely lengthens RTT.

\subsection{Spatial Fairness Skewing on Asymmetric Meshes}
On the NSFNet Continental Mesh, Dijkstra SPF achieved a Jain's Fairness Index of $0.6430$, whereas D3QN achieved $0.6287$.

\subsubsection{Theoretical Root Cause}
Dijkstra SPF calculates shortest paths based purely on static graph topology, naturally spreading traffic across a geometric fan of paths based on node coordinate dispersion. 

In contrast, our D3QN agent identifies the single highest-capacity, lowest-delay lateral bypass path around a congested core and repeatedly routes offloaded flows onto that specific bypass until its utilization reaches $70\%$. While this strategy successfully shields the core from saturation, it creates secondary localized load concentrations on the bypass links, resulting in a slightly higher variance in the link utilization distribution and a marginally lower Jain's Fairness Index.

\subsection{Candidate Path Synthesis Scalability}
While PyTorch neural forward inference executes in just $0.05\text{ ms}$, total decision throughput dropped from $4,625\text{ decisions/sec}$ on a 7-node tree down to $1,121\text{ decisions/sec}$ on a 35-node random graph.

\subsubsection{Theoretical Root Cause}
The computational bottleneck is not the deep neural network: forward matrix multiplication scales as $O(1)$ with respect to graph size. Rather, the scaling bottleneck is Yen's $K$-Shortest Paths algorithm, which executes $K$ iterations of Dijkstra's algorithm over modified subgraphs, having asymptotic time complexity:
\begin{equation}
    T_{\text{Yen}}(|V|, |E|, K) = O(K \cdot |V| \cdot (|E| + |V| \log |V|))
\end{equation}
In a large network with 100+ switches, executing Yen's algorithm dynamically for every incoming flow is computationally infeasible. Our platform resolves this through in-memory path caching (\texttt{\_routing\_path\_cache}): candidate paths are precomputed and cached in $O(1)$ memory tables, decoupling topological path discovery from the real-time neural inference loop.

\subsection{OpenFlow TCAM Space Limitations and Rule Explosion}
Commodity hardware OpenFlow switches utilize Ternary Content-Addressable Memory (TCAM) to perform line-rate, parallel packet header matching. TCAM is silicon-dense, power-hungry, and expensive: typical top-of-rack commodity switches support between 2,000 and 8,000 TCAM flow entries.

If an SDN controller installs a fine-grained, 5-tuple flow rule for every individual micro-flow, a high-concurrency data center experiencing 50,000 concurrent flows will exhaust switch TCAM within seconds. Our platform mitigates rule explosion through:
\begin{enumerate}
    \item \textbf{Subnet and MAC Wildcarding}: Rules match on IP prefixes (\texttt{/24} subnets) and destination MAC addresses rather than ephemeral Layer 4 transport ports.
    \item \textbf{Aggressive Idle Timeouts}: Flow rules are configured with an \texttt{idle\_timeout} of 60 seconds. When a flow ceases transmission, switch hardware autonomously reclaims the TCAM slot without controller intervention.
    \item \textbf{Segment Routing / MPLS Abstraction}: In production backbones, rather than installing per-hop rules, the controller can push MPLS labels or Segment Routing (SRv6) headers at the ingress switch, allowing intermediate transit switches to forward packets at line rate using static label-swapping tables.
\end{enumerate}

\subsection{Thematic Area 1: Theoretical Foundations of Routing \& SDN}

\noindent\textbf{Q1: Traditional OSPF (RFC 2328) has served the Internet reliably for over three decades. Why is an AI-driven SDN approach fundamentally necessary?}
\begin{quote}
\small
\textbf{Model Defense Answer}: OSPF was designed for decentralized resilience under low-bandwidth, quasi-static traffic conditions. Its link administrative metrics are completely static ($10^8 / \text{BW}$), rendering it oblivious to real-time buffer occupancy and link utilization. As verified in our empirical tournament, when traffic surges, OSPF funnels all flows through the identical shortest path, driving core links to 86.7\% saturation and causing 13.5\% packet loss, while lateral links sit idle. SDN provides the global topological visibility, and Deep Reinforcement Learning provides the closed-loop optimization policy necessary to dynamically balance loads across lateral bypasses before buffer overflow occurs.
\end{quote}

\noindent\textbf{Q2: Why does Equal-Cost Multi-Path (ECMP) fail to solve the congestion problem in multi-tier data center fabrics?}
\begin{quote}
\small
\textbf{Model Defense Answer}: ECMP suffers from two fatal limitations: (1) It can only split traffic across paths that share the exact same administrative hop count. If a lateral bypass path is longer by even a single hop, ECMP assigns 0\% traffic to it, even if the primary shortest path is 100\% saturated. (2) ECMP uses oblivious 5-tuple hashing without flow-size awareness. When high-bandwidth elephant flows hash to the same egress port (hash collision), buffer exhaustion occurs, causing severe packet loss and jitter for co-located mice flows, as demonstrated in our tournament where ECMP experienced 6.3\% packet loss on Fat-Tree fabrics.
\end{quote}

\noindent\textbf{Q3: Explain the ``Herd Behavior'' failure mode of greedy dynamic routing heuristics like Least Loaded Routing (LLR).}
\begin{quote}
\small
\textbf{Model Defense Answer}: In discrete telemetry environments, controller polling occurs periodically (e.g., every 3.0 seconds). Greedy heuristics evaluate link utilization at time $t$ and myopically route flows to the lowest-loaded link. Because the telemetry state remains static throughout the polling interval, all flows arriving within that window select the exact same link, driving it into sudden saturation before the next poll. The algorithm then overreacts and shifts all traffic to another link, causing perpetual route flapping. Our D3QN agent avoids this by learning long-term expected returns ($\gamma = 0.95$) with an asymptotic barrier penalty, naturally diffusing traffic across edge-disjoint paths.
\end{quote}

\noindent\textbf{Q4: What is the formal time complexity of Dijkstra's algorithm, and why can it not be recomputed for every packet?}
\begin{quote}
\small
\textbf{Model Defense Answer}: Using a binary min-heap, Dijkstra's algorithm runs in $O((|V| + |E|) \log |V|)$ time; with a Fibonacci heap, it runs in $O(|E| + |V| \log |V|)$ amortized time. In a network handling millions of packets per second, executing graph-wide edge relaxations for every packet arrival would completely overwhelm the CPU. SDN resolves this by computing paths once per flow arrival at the controller, installing directional forwarding rules into switch hardware TCAM for line-rate forwarding.
\end{quote}

\noindent\textbf{Q5: How does Software-Defined Networking decouple control and data planes according to the ONF standard?}
\begin{quote}
\small
\textbf{Model Defense Answer}: In traditional routers, control logic (OSPF/BGP daemons) and data switching ASICs reside inside the same chassis. SDN separates them: switches are relegated to simple packet-matching hardware executing OpenFlow instructions, while control logic is centralized in a software controller (Ryu) communicating over standard OpenFlow 1.3 messages (\texttt{OFPPacketIn}, \texttt{OFPFlowMod}, \texttt{OFPPortStats}).
\end{quote}

\subsection{Thematic Area 2: Deep Reinforcement Learning Mathematics}

\noindent\textbf{Q6: What is the mathematical formulation of a Markov Decision Process (MDP), and how is the Markov property satisfied in your network state?}
\begin{quote}
\small
\textbf{Model Defense Answer}: An MDP is defined by $\langle \mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma \rangle$. The Markov property states that $\mathbb{P}(s_{t+1}|s_t, a_t, \dots, s_0) = \mathbb{P}(s_{t+1}|s_t, a_t)$. In our formulation, state $s_t \in \mathbb{R}^{10}$ captures real-time link utilizations, cumulative path latencies, and global bottleneck loads. Because packet queuing delays and buffer drops at time $t+1$ depend strictly on current link occupancy and the newly routed flow's bandwidth, the state transition probability is memoryless, satisfying the Markov property.
\end{quote}

\noindent\textbf{Q7: Why choose a Dueling Q-Network over a standard Deep Q-Network?}
\begin{quote}
\small
\textbf{Model Defense Answer}: In network routing, estimating the overall quality of the network state $V(s)$ is vital regardless of which specific candidate path is chosen. If all paths are congested, the state itself is poor. A standard DQN must learn the value of each action independently, requiring redundant updates. The Dueling architecture decomposes the network into a scalar value stream $V(s)$ and an advantage stream $A(s, a)$. By subtracting the mean advantage, $Q(s, a) = V(s) + (A(s, a) - \frac{1}{|\mathcal{A}|}\sum A)$, we guarantee unique identifiability and achieve faster, more stable policy convergence.
\end{quote}

\noindent\textbf{Q8: How does Double Q-Learning eliminate overestimation maximization bias?}
\begin{quote}
\small
\textbf{Model Defense Answer}: Standard Q-learning uses $\max_{a'} Q(s', a'; \theta^-)$ in the target value, which suffers from Jensen's inequality: $\mathbb{E}[\max X] \ge \max \mathbb{E}[X]$. In noisy telemetry environments, this causes the agent to systematically overestimate suboptimal paths. Double DQN decouples action selection from action evaluation: the online network ($\theta$) selects the greedy action $a^* = \arg\max_a Q(s', a; \theta)$, while the target network ($\theta^-$) evaluates its value: $Y_t = r + \gamma Q(s', a^*; \theta^-)$, provably eliminating maximization bias.
\end{quote}

\noindent\textbf{Q9: Derive the importance sampling weight formula in Prioritized Experience Replay (PER) and explain why $\beta$ must be annealed to 1.0.}
\begin{quote}
\small
\textbf{Model Defense Answer}: PER samples transitions non-uniformly with probability $P(i) = p_i^\alpha / \sum p_k^\alpha$, which introduces estimation bias into stochastic gradient descent. To correct this, Importance Sampling weights are applied: $w_i = (N \cdot P(i))^{-\beta} / \max_j w_j$. Parameter $\beta$ controls the degree of bias correction. Early in training, unbiasedness is less critical than rapid gradient discovery ($\beta_0 = 0.4$); near convergence, full correction ($\beta \to 1.0$) is mathematically necessary to guarantee asymptotic convergence to the true Bellman expectation.
\end{quote}

\noindent\textbf{Q10: Why did you employ the Smooth L1 (Huber) loss function instead of standard Mean Squared Error (MSE)?}
\begin{quote}
\small
\textbf{Model Defense Answer}: MSE has a quadratic gradient $\nabla_\theta \mathcal{L} = 2\delta \nabla_\theta Q$. When sudden traffic bursts occur, the temporal difference error $\delta_i$ can spike to 50.0, generating huge gradient updates that destabilize the optimizer. Huber loss is piecewise: quadratic for $|\delta| \le 1.0$, and linear ($|\delta| - 0.5$) for $|\delta| > 1.0$. The gradient is strictly clipped to $\pm 1.0$ for large errors, preventing exploding gradients while preserving smooth quadratic convergence near the optimum.
\end{quote}

\section{Software Quality Assurance and Testing Philosophy}
To ensure commercial-grade reliability, maintainability, and reproducibility, the entire codebase was engineered under rigorous test-driven development (TDD) principles. Network control plane software is notoriously prone to concurrency bugs, race conditions between telemetry polling and packet arrival, memory leaks in replay buffers, and silent deadlocks in asynchronous green threads.

Our quality assurance framework guarantees software correctness across four decoupled validation tiers:
\begin{enumerate}
    \item \textbf{Unit and Component Testing (\texttt{test\_suite.py})}: 32 automated unit and integration tests validating individual algorithms, data structures, configuration resolution, and REST API telemetry endpoints.
    \item \textbf{Closed-Loop Network Dynamics Testing}: Verification of continuous bandwidth accumulation, flow expiration release, and Polyak soft target tracking.
    \item \textbf{Automated Benchmark and Stress Testing Suites}: Multi-topology benchmarking scripts (\texttt{run\_benchmarks.sh}, \texttt{stress\_test\_blind\_topologies.py}).
    \item \textbf{Headless Dashboard and REST API Testing (\texttt{test\_dashboard\_headless.py})}: Web telemetry verification via automated HTTP client test harnesses asserting schema compliance, JSON serialization, and sub-millisecond inference endpoints.
\end{enumerate}

\section{Retrospective Summary of Research Achievements}
This graduation project engineered, implemented, and rigorously evaluated an autonomous, production-ready \textbf{Deep Reinforcement Learning (DRL) Traffic Engineering Platform} built upon the \textbf{Ryu OpenFlow 1.3 SDN Controller}, the \textbf{PyTorch Deep Learning Framework}, and the \textbf{Mininet Network Emulator}. The system replaces static, oblivious shortest-path routing with an intelligent, closed-loop telemetry-driven control policy powered by a \textbf{Dueling Double Deep Q-Network (D3QN)} and a binary \textbf{SumTree Prioritized Experience Replay (PER)} buffer.

Through an automated, multi-topology quantitative routing tournament benchmarking our D3QN agent against five classical routing paradigms---OSPF (RFC 2328), Dijkstra SPF, ECMP, Widest Shortest Path (WSP/CSPF), and Greedy Least Loaded Routing (LLR)---across five topologically diverse networks, the platform demonstrated decisive performance breakthroughs:
\begin{enumerate}
    \item \textbf{Substantial Congestion Relief}: Slashed peak bottleneck link utilization from $86.74\%$ down to \textbf{$19.40\%$} on Spine-Leaf fabrics (a \textbf{$-77.6\%$ relative reduction}) and from $65.48\%$ down to \textbf{$23.29\%$} on Fat-Tree Clos fabrics (a \textbf{$-64.4\%$ relative reduction}).
    \item \textbf{Significant Latency Optimization}: Reduced end-to-end path latency from $34.71\text{ ms}$ down to \textbf{$2.67\text{ ms}$} on Spine-Leaf (a \textbf{$92.3\%$ latency savings}), and from $25.89\text{ ms}$ down to \textbf{$7.00\text{ ms}$} on Fat-Tree Clos.
    \item \textbf{Comprehensive Jitter Suppression}: Suppressed RFC 3393 packet delay variation by over \textbf{$85\%$--$95\%$} across all evaluated topologies, delivering deterministic QoS for real-time video streaming and industrial control.
    \item \textbf{Eradication of Buffer Dropouts}: Reduced drop-tail packet loss from $13.47\%$ down to \textbf{$0.010\%$} on Spine-Leaf, and from $9.30\%$ down to \textbf{$0.012\%$} on Fat-Tree Clos.
    \item \textbf{High-Throughput Decision Plane}: Sustained neural routing decision throughput exceeding \textbf{$2,400\text{ to } 4,600\text{ decisions/second}$} on commodity CPU hardware, handling a 500-flow avalanche within $176.8\text{ ms}$ with zero flow drops.
    \item \textbf{Verified Zero-Shot Generalization}: Demonstrated immediate anti-congestion steering ($+7.6\%$ to $+12.3\%$ bottleneck relief) on dynamically generated, unseen Erd\H{o}s--R\'enyi random graphs up to 35 nodes without requiring model retraining.
\end{enumerate}

\section{Real-World Hardware Deployment Considerations}
While validated on Mininet emulating OpenFlow 1.3 switches, transitioning this platform to bare-metal enterprise or cloud data center environments involves key engineering considerations:
\begin{enumerate}
    \item \textbf{Physical TCAM Constraints}: Hardware switches (e.g., Broadcom Tomahawk or Trident ASICs) possess limited TCAM tables. Production deployments must utilize destination IP prefix aggregation (\texttt{/24} subnets) or Segment Routing (SRv6) to keep flow rule counts within hardware limits.
    \item \textbf{Open vSwitch Kernel Acceleration}: In virtualized cloud environments (OpenStack, Kubernetes), switches run as Open vSwitch (OVS). Utilizing OVS with Data Plane Development Kit (DPDK) or eBPF/XDP bypasses the Linux kernel network stack, enabling line-rate 100~Gbps packet switching per server.
    \item \textbf{Clustered High-Availability SDN Controllers}: In carrier networks, a single centralized controller introduces a single point of failure. Deploying a distributed Ryu or ONOS cluster utilizing Raft consensus (e.g., via etcd) guarantees high availability and distributed load sharing.
\end{enumerate}

\section{Future Research Directions}
This research opens several promising avenues for future doctoral, academic, and industrial investigation:

\subsection{Multi-Agent Cooperative Reinforcement Learning (MADRL)}
In continental or multi-domain networks, centralized telemetry aggregation introduces control plane latency. Deploying decentralized Multi-Agent Reinforcement Learning (e.g., Multi-Agent PPO / MAPPO) where each autonomous edge or aggregation switch hosts a lightweight local policy network communicating via Graph Neural Networks (GNNs) represents a compelling evolutionary step.

\subsection{Continuous Action Space Flow Splitting via Soft Actor-Critic (SAC)}
Our current architecture selects among $K=4$ discrete candidate paths. Transitioning to continuous action spaces using actor-critic algorithms (such as Soft Actor-Critic / SAC \cite{lillicrap2015continuous}) would allow the neural network to output continuous flow splitting ratios $[\alpha_1, \alpha_2, \dots, \alpha_K]$ such that $\sum \alpha_i = 1.0$. These ratios can be mapped directly into OpenFlow Select Group table bucket weights, enabling microsecond-granularity adaptive multipath flow sharding.

\subsection{P4 Programmable Data Planes and In-Band Network Telemetry (INT)}
While OpenFlow 1.3 polling provides robust macroscopic telemetry, it remains constrained by the 3.0-second polling interval. Implementing the traffic engineering policy on P4-programmable switches (e.g., Intel Tofino ASICs) would enable In-Band Network Telemetry (INT). Switches can embed real-time queue occupancies, link utilization counters, and microsecond timestamps directly into packet headers at line rate, enabling sub-millisecond closed-loop congestion avoidance.

\section{Proof of Bellman Optimality via Banach Fixed Point Theorem}
Let $\mathcal{B}(\mathcal{S} \times \mathcal{A})$ denote the Banach space of all bounded real-valued functions over state-action space $\mathcal{S} \times \mathcal{A}$, equipped with the supremum norm (infinity norm):
\begin{equation}
    \|Q\|_\infty = \sup_{s \in \mathcal{S}, a \in \mathcal{A}} |Q(s, a)|
\end{equation}
We define the Bellman Optimality Operator $\mathcal{T}^*: \mathcal{B}(\mathcal{S} \times \mathcal{A}) \to \mathcal{B}(\mathcal{S} \times \mathcal{A})$ by:
\begin{equation}
    (\mathcal{T}^* Q)(s, a) = \mathcal{R}(s, a) + \gamma \sum_{s' \in \mathcal{S}} \mathcal{P}(s' \mid s, a) \max_{a' \in \mathcal{A}} Q(s', a')
\end{equation}

\begin{theorem}[Contraction Mapping of Bellman Optimality Operator]
If the discount factor satisfies $\gamma \in [0, 1)$, then $\mathcal{T}^*$ is a $\gamma$-contraction mapping on $(\mathcal{B}(\mathcal{S} \times \mathcal{A}), \|\cdot\|_\infty)$.
\end{theorem}

\begin{proof}
Let $Q_1, Q_2 \in \mathcal{B}(\mathcal{S} \times \mathcal{A})$. For any state $s \in \mathcal{S}$ and action $a \in \mathcal{A}$:
\begin{align}
    |(\mathcal{T}^* Q_1)(s, a) - (\mathcal{T}^* Q_2)(s, a)| &= \left| \gamma \sum_{s'} \mathcal{P}(s' \mid s, a) \left( \max_{a'} Q_1(s', a') - \max_{a''} Q_2(s', a'') \right) \right| \nonumber \\
    &\le \gamma \sum_{s'} \mathcal{P}(s' \mid s, a) \left| \max_{a'} Q_1(s', a') - \max_{a''} Q_2(s', a'') \right|
\end{align}
Using the algebraic inequality $|\max_x f(x) - \max_x g(x)| \le \max_x |f(x) - g(x)|$:
\begin{align}
    |(\mathcal{T}^* Q_1)(s, a) - (\mathcal{T}^* Q_2)(s, a)| &\le \gamma \sum_{s'} \mathcal{P}(s' \mid s, a) \max_{a'} |Q_1(s', a') - Q_2(s', a')| \nonumber \\
    &\le \gamma \sum_{s'} \mathcal{P}(s' \mid s, a) \|Q_1 - Q_2\|_\infty \nonumber \\
    &= \gamma \|Q_1 - Q_2\|_\infty \sum_{s'} \mathcal{P}(s' \mid s, a) \nonumber \\
    &= \gamma \|Q_1 - Q_2\|_\infty
\end{align}
Taking the supremum over all $s \in \mathcal{S}$ and $a \in \mathcal{A}$:
\begin{equation}
    \|\mathcal{T}^* Q_1 - \mathcal{T}^* Q_2\|_\infty \le \gamma \|Q_1 - Q_2\|_\infty
\end{equation}
Since $\gamma < 1$, $\mathcal{T}^*$ is a strict contraction. By the Banach Fixed Point Theorem, there exists a unique fixed point $Q^* \in \mathcal{B}(\mathcal{S} \times \mathcal{A})$ such that $\mathcal{T}^* Q^* = Q^*$, and value iteration converges geometrically:
\begin{equation}
    \|Q_{k+1} - Q^*\|_\infty \le \gamma^k \|Q_0 - Q^*\|_\infty
\end{equation}
which proves asymptotic convergence to the optimal routing value function.
\end{proof}

\section{Derivation of Double Q-Learning Bias Elimination}
Consider a state $s$ with $M$ candidate actions whose true values are equal: $Q^*(s, a_i) = V^*$. Suppose our value estimates are subject to zero-mean random estimation noise $\epsilon_i$:
\begin{equation}
    \hat{Q}(s, a_i) = V^* + \epsilon_i, \quad \mathbb{E}[\epsilon_i] = 0, \quad \text{Var}(\epsilon_i) = \sigma^2
\end{equation}

\subsection{Standard Q-Learning Bias}
In standard Q-learning, the target value takes the maximum across action estimates:
\begin{equation}
    \mathbb{E}\left[ \max_i \hat{Q}(s, a_i) \right] = V^* + \mathbb{E}\left[ \max_{i=1,\dots,M} \epsilon_i \right]
\end{equation}
If $\epsilon_i \sim \mathcal{N}(0, \sigma^2)$, then by extreme value theory for independent Gaussians:
\begin{equation}
    \mathbb{E}\left[ \max_{i=1,\dots,M} \epsilon_i \right] \approx \sigma \sqrt{2 \ln M} > 0 \quad \forall M \ge 2
\end{equation}
This positive bias scales with $\sqrt{\ln M}$, causing standard DQN to systematically overestimate expected returns on candidate paths with noisy latency measurements.

\subsection{Double Q-Learning Decoupling}
In Double Q-learning, action selection is performed by set of weights $\theta_1$, while evaluation is performed by independent set $\theta_2$:
\begin{equation}
    a^* = \arg\max_i \hat{Q}(s, a_i; \theta_1)
\end{equation}
The evaluated target value is:
\begin{equation}
    \mathbb{E}\left[ \hat{Q}(s, a^*; \theta_2) \right] = \mathbb{E}\left[ V^* + \epsilon_2(a^*) \right] = V^* + \mathbb{E}[\epsilon_2(a^*)]
\end{equation}
Because $\theta_2$ is statistically independent of $\theta_1$, the estimation noise $\epsilon_2$ is independent of the index selection $a^*$:
\begin{equation}
    \mathbb{E}[\epsilon_2(a^*)] = \sum_{k=1}^M \mathbb{P}(a^* = k) \cdot \mathbb{E}[\epsilon_2(k)] = \sum_{k=1}^M \mathbb{P}(a^* = k) \cdot 0 = 0
\end{equation}
Thus, Double Q-learning completely eliminates maximization overestimation bias, proving theoretical stability.

\section{Derivation of Importance Sampling Correction in PER}
Under Prioritized Experience Replay, transitions are drawn from distribution $P(i) = p_i^\alpha / \sum p_k^\alpha$ instead of the true empirical replay distribution $U(i) = 1/N$.

The expected value of gradient updates under the true uniform distribution is:
\begin{equation}
    \mathbb{E}_{i \sim U}[\nabla_\theta \mathcal{L}_i] = \sum_{i=1}^N \frac{1}{N} \nabla_\theta \mathcal{L}_i
\end{equation}
Under prioritized sampling distribution $P(i)$, the expectation is:
\begin{equation}
    \mathbb{E}_{i \sim P}\left[ w_i \nabla_\theta \mathcal{L}_i \right] = \sum_{i=1}^N P(i) \cdot w_i \nabla_\theta \mathcal{L}_i
\end{equation}
Equating the two expectations to eliminate bias:
\begin{equation}
    P(i) \cdot w_i = \frac{1}{N} \implies w_i = \frac{1}{N \cdot P(i)}
\end{equation}
Raising to exponent $\beta$ and normalizing by $\max_j w_j$ yields the standard PER Importance Sampling weight formula:
\begin{equation}
    \tilde{w}_i = \left( \frac{1}{N \cdot P(i)} \right)^\beta \Big/ \max_j w_j
\end{equation}
When $\beta = 1.0$, $\mathbb{E}_{i \sim P}[\tilde{w}_i \nabla \mathcal{L}_i] \propto \mathbb{E}_{i \sim U}[\nabla \mathcal{L}_i]$, guaranteeing that prioritized stochastic gradient descent converges to the true expected value.

\section{Derivation of the M/M/1 Queuing Delay Model}
Consider an OpenFlow switch output port buffer modeled as a birth-death Markovian queuing system $M/M/1$:
\begin{itemize}
    \item Arrival rate: $\lambda$ packets/second (Poisson process).
    \item Service rate: $\mu = C / \bar{L}$ packets/second (exponentially distributed service times).
    \item Traffic intensity (link utilization): $\rho = \lambda / \mu < 1$.
\end{itemize}

Let $P_n$ denote the steady-state probability that exactly $n$ packets reside in the queue buffer. The balance equations state:
\begin{equation}
    \lambda P_{n-1} = \mu P_n \implies P_n = \left(\frac{\lambda}{\mu}\right)^n P_0 = \rho^n P_0
\end{equation}
Since $\sum_{n=0}^\infty P_n = 1$:
\begin{equation}
    P_0 \sum_{n=0}^\infty \rho^n = \frac{P_0}{1 - \rho} = 1 \implies P_0 = 1 - \rho
\end{equation}
Thus, $P_n = (1 - \rho)\rho^n$. The mean number of packets in the system $L$ is:
\begin{equation}
    L = \sum_{n=0}^\infty n P_n = (1 - \rho) \sum_{n=0}^\infty n \rho^n = (1 - \rho) \frac{\rho}{(1 - \rho)^2} = \frac{\rho}{1 - \rho}
\end{equation}
Applying Little's Law ($L = \lambda W$), the average time $W$ a packet spends in the system (transmission delay + queuing delay) is:
\begin{equation}
    W = \frac{L}{\lambda} = \frac{\rho}{\lambda(1 - \rho)} = \frac{1}{\mu(1 - \rho)} = \frac{1}{\mu - \lambda}
\end{equation}
Subtracting the base transmission delay $1/\mu$, the average queuing delay $W_q$ is:
\begin{equation}
    W_q = W - \frac{1}{\mu} = \frac{1}{\mu - \lambda} - \frac{1}{\mu} = \frac{\lambda}{\mu(\mu - \lambda)} = \frac{\rho}{\mu(1 - \rho)}
\end{equation}
This establishes the theoretical foundation for Equation~\ref{eq:queuing_delay_formula}.

\section{Proof of Congestion Avoidance via Asymptotic Barrier Function}
\label{sec:proof_barrier}
Let $\mathcal{P}$ denote the set of simple paths connecting ingress switch $s$ and egress switch $d$. For each path $P \in \mathcal{P}$, let $\rho_{\max}(P) = \max_{e \in P} \rho_e$ denote its bottleneck link utilization. The multi-objective reward includes an exponential congestion barrier:
\begin{equation}
    \Phi_{\text{cong}}(P) = \begin{cases}
        \exp\left(\frac{\rho_{\max}(P) - \rho_{\text{thresh}}}{1.0 - \rho_{\max}(P)}\right) - 1, & \text{if } \rho_{\max}(P) > \rho_{\text{thresh}} \\
        0, & \text{otherwise}
    \end{cases}
\end{equation}
where $\rho_{\text{thresh}} = 0.70$.

\begin{theorem}[Asymptotic Congestion Barrier Divergence]
As the bottleneck utilization of any path $P$ approaches link capacity ($\rho_{\max}(P) \to 1^-$), the barrier penalty diverges to positive infinity:
\begin{equation}
    \lim_{\rho_{\max}(P) \to 1^-} \Phi_{\text{cong}}(P) = +\infty
\end{equation}
Furthermore, if there exists at least one alternate candidate path $P_{\text{alt}} \in \mathcal{P}$ with $\rho_{\max}(P_{\text{alt}}) \le \rho_{\text{thresh}}$, then under optimal Q-values, the policy satisfies:
\begin{equation}
    \lim_{\rho_{\max}(P) \to 1^-} \mathbb{P}\left(\pi(s) = P\right) = 0
\end{equation}
guaranteeing deterministic avoidance of saturated links.
\end{theorem}

\begin{proof}
Let $x = \rho_{\max}(P)$. For $x \in (\rho_{\text{thresh}}, 1)$:
\begin{equation}
    \lim_{x \to 1^-} \frac{x - \rho_{\text{thresh}}}{1 - x} = \lim_{\epsilon \to 0^+} \frac{1 - \epsilon - \rho_{\text{thresh}}}{\epsilon} = +\infty
\end{equation}
Because the exponential function $\exp(u)$ is strictly monotonically increasing on $\mathbb{R}$ and $\lim_{u \to \infty} \exp(u) = \infty$, it follows that:
\begin{equation}
    \lim_{x \to 1^-} \Phi_{\text{cong}}(P) = \lim_{u \to \infty} (\exp(u) - 1) = +\infty
\end{equation}
The reward function is defined as $\mathcal{R}(s, P) = - [w_{\text{util}} \rho_{\max}(P) + w_{\text{lat}} D(P) + w_{\text{jit}} J(P) + w_{\text{loss}} P_{\text{loss}}(P) + w_{\text{cong}} \Phi_{\text{cong}}(P)]$. As $\rho_{\max}(P) \to 1^-$, $\mathcal{R}(s, P) \to -\infty$.

By the Bellman optimality equation, $Q^*(s, P) = \mathcal{R}(s, P) + \gamma \sum_{s'} \mathcal{P}(s' \mid s, P) V^*(s')$. Since all subsequent state values $V^*(s')$ are bounded, $\lim_{\rho_{\max}(P) \to 1^-} Q^*(s, P) = -\infty$.

Conversely, for $P_{\text{alt}}$, $\Phi_{\text{cong}}(P_{\text{alt}}) = 0$, so $\mathcal{R}(s, P_{\text{alt}})$ is strictly finite. Under the greedy or softmax policy $\pi(a \mid s) = \frac{\exp(Q(s, a)/\tau)}{\sum_{b} \exp(Q(s, b)/\tau)}$, as $Q^*(s, P) \to -\infty$:
\begin{equation}
    \mathbb{P}\left(\pi(s) = P\right) = \frac{\exp(Q^*(s, P)/\tau)}{\exp(Q^*(s, P_{\text{alt}})/\tau) + \sum_{b \ne P, P_{\text{alt}}} \exp(Q^*(s, b)/\tau)} \to 0
\end{equation}
which guarantees that the agent will never choose a saturated path when an uncongested alternative exists.
\end{proof}

\section{Dueling Q-Network and Agent Engine (\texttt{agent/dqn\_router.py})}
Listing~\ref{lst:dqn_router_code} presents the core PyTorch neural network class implementing Layer Normalization and dueling stream aggregation.

\begin{lstlisting}[language=Python, caption={PyTorch Dueling Q-Network Architecture with Layer Normalization}, label={lst:dqn_router_code}]
import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np

class DuelingQNetwork(nn.Module):
    def __init__(self, state_size=10, action_size=4):
        super(DuelingQNetwork, self).__init__()
        # Shared Feature Extraction Trunk
        self.shared_fc1 = nn.Linear(state_size, 64)
        self.ln1 = nn.LayerNorm(64)
        self.shared_fc2 = nn.Linear(64, 128)
        self.ln2 = nn.LayerNorm(128)
        self.relu = nn.ReLU()

        # State-Value Stream V(s)
        self.val_fc1 = nn.Linear(128, 64)
        self.val_ln = nn.LayerNorm(64)
        self.val_out = nn.Linear(64, 1)

        # Action-Advantage Stream A(s, a)
        self.adv_fc1 = nn.Linear(128, 64)
        self.adv_ln = nn.LayerNorm(64)
        self.adv_out = nn.Linear(64, action_size)

    def forward(self, state):
        x = self.relu(self.ln1(self.shared_fc1(state)))
        x = self.relu(self.ln2(self.shared_fc2(x)))

        val = self.relu(self.val_ln(self.val_fc1(x)))
        val = self.val_out(val)

        adv = self.relu(self.adv_ln(self.adv_fc1(x)))
        adv = self.adv_out(adv)

        # Identifiability Aggregation: subtract mean advantage
        q_values = val + (adv - adv.mean(dim=-1, keepdim=True))
        return q_values
\end{lstlisting}

\section{Binary SumTree Prioritized Replay Buffer (\texttt{agent/prioritized\_replay.py})}
Listing~\ref{lst:sumtree_code} presents the complete non-recursive binary SumTree implementation.

\begin{lstlisting}[language=Python, caption={Iterative Binary SumTree and Prioritized Experience Replay}, label={lst:sumtree_code}]
import numpy as np

class SumTree:
    def __init__(self, capacity):
        self.capacity = capacity
        self.tree = np.zeros(2 * capacity - 1, dtype=np.float32)
        self.data = np.zeros(capacity, dtype=object)
        self.write_ptr = 0
        self.n_entries = 0

    def total(self):
        return self.tree[0]

    def add(self, p, data):
        idx = self.write_ptr + self.capacity - 1
        self.data[self.write_ptr] = data
        self.update(idx, p)
        self.write_ptr = (self.write_ptr + 1) % self.capacity
        if self.n_entries < self.capacity:
            self.n_entries += 1

    def update(self, idx, p):
        change = p - self.tree[idx]
        self.tree[idx] = p
        while idx > 0:
            idx = (idx - 1) // 2
            self.tree[idx] += change

    def get(self, s):
        idx = 0
        while idx < self.capacity - 1:
            left = 2 * idx + 1
            right = left + 1
            if s <= self.tree[left]:
                idx = left
            else:
                s -= self.tree[left]
                idx = right
        data_idx = idx - self.capacity + 1
        return idx, self.tree[idx], self.data[data_idx]
\end{lstlisting}

\section{State Feature Vector Extraction (\texttt{controller/state\_manager.py})}
Listing~\ref{lst:state_features_code} shows the extraction of the 10-dimensional state vector from the active NetworkX graph.

\begin{lstlisting}[language=Python, caption={Normalized 10-Dimensional State Extraction in StateManager}, label={lst:state_features_code}]
def get_routing_state_features(self, candidate_paths):
    state = np.zeros(10, dtype=np.float32)
    if not candidate_paths or len(candidate_paths) == 0:
        return state

    # Feature 0: Normalized hop count of shortest path
    shortest_path = candidate_paths[0]
    hops = max(1, len(shortest_path) - 1)
    state[0] = np.clip(hops / 10.0, 0.1, 1.0)

    # Features 1-4: Peak link utilization on up to 4 candidate paths
    # Features 5-8: Normalized cumulative propagation latency
    for i in range(min(4, len(candidate_paths))):
        path = candidate_paths[i]
        path_util = 0.0
        path_lat = 0.0
        for u, v in zip(path[:-1], path[1:]):
            if self.graph.has_edge(u, v):
                edge_data = self.graph[u][v]
                path_util = max(path_util, edge_data.get('utilization', 0.0))
                path_lat += edge_data.get('latency', 2.0)
        state[1 + i] = np.clip(path_util, 0.0, 1.0)
        state[5 + i] = np.clip(path_lat / 50.0, 0.0, 1.0)

    # Feature 9: Global peak link utilization across entire network
    max_util = 0.0
    for u, v, data in self.graph.edges(data=True):
        max_util = max(max_util, data.get('utilization', 0.0))
    state[9] = np.clip(max_util, 0.0, 1.0)

    return state
\end{lstlisting}
